# 芦木地下茎现行规则与接入边界

本页按 2026-10-23 用户最新确认整理，优先于交接文档中较早的阶段性描述。

## 身份、数量与范围

- 同源地下茎、幼丛及其长成的地上植株属于同一个生物学个体，使用地下系统 UUID。地上每株仍保留独立的结构记录 UUID，以管理阶段、损伤与生长；通过 `RhizomeIndividualIdentity` 解析共同身份。
- 种群数量按实际地上植株计数，不按地下系统去重。自然种群成年 1～8 株、幼丛/丛合计 1～6 株、亚成体 1～6 株。自然植株及其地下系统均为 STATIC，一次生成，不启动生长队列。
- `RhizomePopulation` 注册物种阶段分类；`RhizomeNaturalPopulationPlan` 校验一次选定的自然数量、身份与地下归属。它是元数据计划，不是实际世界生成 Feature，也不替代完整结构空间预检。
- `RhizomeNaturalStructurePlan` 将这份元数据与每株完整结构、全部地下节点的原/目标状态合并。要求每株及地下节点恰好覆盖一次、根位有实际地上结构、写入不越界、不同快照一致、自然端点标记正确。`expectedStates()` 可供未来整组预检读取；构造及查询均不读取世界、不消耗随机数、不写入存档。
- `RhizomeNaturalPreflight.check` 在服务器线程进行整组只读预检：先确认全部读取位置及双格装饰另一半的高度、世界边界和活动区块，再比较原状态并检查已有身份占位。地上复用共享替换策略，地下复核路径白名单；返回统一快照及额外无掉落清理位置，不登记个体、不消耗生成凭据。区块检查按区块去重，方块方法调用后复核状态与归属。
- `RhizomeNaturalPlacement.placeOnce` 是活动区块内的整组放置入口，不能循环调用单株放置器来替代。调用者先确保规划所需区块可用；入口在规划前领取稳定规则/候选位置的一次凭据，生态拒绝或空间/写入失败不重抽、不排队重试。生态条件仍由物种规划器决定。
- 包内 `RhizomeNaturalRegistration` 提供整组元数据登记会话：打开时重做预检并锁住个体、地下系统两个存储；实际方块、额外装饰清理及未改依赖全部符合目标后，才整组登记身份、部件、种群计数和地下归属。普通公共变更在会话期间拒绝重入；登记异常撤销本次元数据，STATIC 不增加成长或补生队列。
- 方块按 Y/X/Z 稳定顺序写入，延后邻居更新并抑制装饰掉落；写入失败倒序恢复本次仍保留目标状态的方块，不覆盖其他模组的新状态。无法完整恢复时保留拟结构元数据和异常标记。成功后解锁，按实际状态通知邻居，再复核方块、依赖和元数据；异常返回 `RECOVERY_REQUIRED`，不自动重试。
- 此入口不是 WorldGenRegion Feature，尚未注册具体芦木模板或群系规则。其他模组回调产生的实体/音效/物品等外部副作用和跨 SavedData 断电原子性不在回滚保证内。
- 同源扩展始终限制在原固定 32×32 的 XZ 区域。自然数量范围不直接当作人工栽培的硬上限。

## 每株 C/D 额度与共同名额

- 每株进入 C 阶段时，从自己的根位建立一对端点，每端独立获得一次 3～5 格长度。进入 D 时，该株每端再追加一次 2～5 格。
- 同源后代的额度仍存入原系统，既不建立新生物学个体，也不刷新其他植株的额度。失败规划、转向、切断和重载不重抽长度。
- 系统共享幼丛名额仍为初始化时确定的 2～3 个。长成 C/D 后继续占额，只有实际注销地上活体并解除关联才释放。
- C 结构提交完成后调用 `RhizomeInitialization.create`，D 结构提交完成后调用 `RhizomeStageGrowth.beginD`。调用后重新读取个体快照。阶段的实际方块形状由物种适配器提供。

## 路径和跨系统覆盖

- 自己系统的地下茎不是可覆盖路径；规划器尝试其他方向或其他有效端点。
- 选路与模型提交共用占位规则：排除横向/竖向节点、纤维根及保留的历史分支根位，再读取候选世界状态。两条侧路只对合法者抽选，仅为最终方向复制系统模型。整套系统入口在抽选前拒绝静止、过期、只读、恢复中或正在提交的调用。
- 可覆盖其他系统的实际地下茎方块，仅覆盖段转移归属。原系统其余节点、个体、名额和剩余额度保持原身份，不合并系统。
- 物理节点归属唯一。旧系统的连接点、历史根位或端点引用可能指向已被覆盖的位置；这不赋予其从外国节点继续延伸的权利。
- 横向和竖向路径先完整检查，再统一写入。空气、水源、水流、苔藓及允许的苔藓可转化基质可转换；指定草、花、蕨和地毯等装饰可无掉落覆盖，双格装饰一起处理。
- 保留水源/水流的精确流体状态。真正发生方块变化时照常通知邻居与侦测器；没有实际状态变化的纯归属转移不伪造脉冲。
- 出苗支持至多两格连续水深，不预检成年体空间。具体出苗规则沿用 `RhizomeShootPath`。

## 生长点与生命周期

- `RhizomeBlock.GROWTH_POINT` 是同一地下茎方块的布尔状态，不新增生长点物品，也不需要方块实体。生长后旧端恢复普通状态，新端显示生长点；破坏统一掉普通地下茎。
- 自然系统可按完整地下形状标记端点外观，外观不激活 STATIC 系统。
- 基础地下茎禁止活塞推动，以免坐标归属失效。机械移动结构的专用迁移适配尚未实现。
- 补生按系统等待 48,000 活动 tick，满额停止；实际注销腾位后重新等待。区块不活动时不补算，恢复异常时冻结。
- 普通节点破坏注销该节点，不拆分生物学身份，不自动释放地上植株名额。

## 存档、性能和后续接入

- 地下系统存档 Version 6 保存各株分支根位及 C/D 预算；兼容 Version 1～5。旧存档不凭空补发后代预算，初始化仍受持久化标记保护。
- 路径使用坐标索引、局部候选缓存及到期队列，不增加全世界逐 tick 扫描。跨系统转移与生长点迁移纳入同一次内存事务；无法完整回滚时冻结相关系统。不同 SavedData 文件不保证断电时磁盘原子性。
- 尚待物种适配器注册实际芦木方块、物品、阶段、模型、材质、出苗回调与自然生成模板。基础 `RhizomeBlock` 不自带水流状态实现，物种必须提供能通过精确流体验证的实际状态。
- 当前状态查询可供未来 Jade 提供器使用，尚不表示 Jade 网络/UI 已接好。
- 本轮仅做代码与 Git 差异静态检查，不运行 Gradle。后续需本地编译并验证分支额度重载、同源占额、跨系统覆盖、端点迁移、破坏注销、流体保留及失败回滚。
