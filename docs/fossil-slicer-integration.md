# 化石切片机接入与验证边界

第29条确认：纯手动，无燃料或红石供能。沿固定导轨从左端拖到右端完成一次切割，可以暂停和反向；一次消耗1个煤化／印痕原料，产1片对应切片，余石消失，无副产物。中途松开取消；在终点松开会等待服务器确认已经发出的进度，不自动开始下一片。

## 实际注册与数据

- `life_sanctuary:fossil_slicer`：完整方块、物品、方块实体和菜单，右键打开双槽界面；非动态方块模型，无方块实体渲染器或ticker。
- `life_sanctuary:fossil_slice`：通用切片物品。CUSTOM_DATA内FossilSlice V1保存真实输入物品ID、标本键、形态及可选石头／深板岩基质。显示名由对应正式原料名称派生；无效身份使用通用名称，未知版本不改写原始数据。
- 输入槽0仅接受本模组命名空间内、FossilMaterial.identify认可的未切片BlockItem。中央大框对应真实加工／产物槽1，禁止直接插入；空闲时从输入槽移入1份原料，切割完成在原位替换为1片，取走后再补下一份。原料、成品均可手动取回，Shift转移可用。上面／侧面仅补输入槽，下面仅抽有效成品，不能提前抽走中央原料；无方向能力也阻止抽取待切原料。自动化不会启动切割。
- 方块被破坏时掉落实际两槽内容，方块掉落表只产机器本体，不复制库存。菜单关闭、离开距离、机器移除或输入身份变化取消操作，进度不存档。

输入身份来自真实FossilMaterial方块，不能靠任意物品自报Species或伪造原料名单。正式煤化／印痕材料尚未注册，当前不填入猜测物种ID；内容作者注册上述方块适配器后自动获得切片能力。没有新增玩家未指定的机器合成配方。

## 服务端提交与性能

FossilSlicingRules提供原生菜单按钮协议：开始、0～64的位置、取消，均在有符号字节范围内。服务器校验当前菜单、玩家距离、实际方块实体、空光标、操作归属和每步移动限制；同一服务器tick最多接受一步，允许反向，拒绝越界、跳步及重复终点结算。此限制用于进度校验，不宣称能够区分真实鼠标与修改客户端。

每台机器一次只允许一人操作；缓冲输入槽增减不影响已经摆在中央的那一份。移入中央时只移动库存、不消耗，取消后原料仍在中央；完成时服务器验证中央仍为原来的一份原料，再一次主线程提交替换为1片。成品占据中央时不能切下一份。重新补料递增加工位版本，即使取走又补入同种原料，也不能继承前一份的切割进度。重复完成命令不能再次产出，取消不返还额外物品。关闭菜单释放操作归属，旧菜单不能释放后来者。

服务器只对打开的菜单同步进度和状态，预览按中央原料物品及组件缓存。自动补料仅在库存变化或区块加载时触发，关闭机器没有加工或扫描任务。客户端每tick至多发送一次进度，显示服务器确认位置。中央大框将原料／成品物品模型放大三倍显示，框内可取回物品，导轨位于框下。实际细节依赖正式模型；机器模型暂用平滑石头贴图，切片暂用纸贴图，均为占位资源，交由模型制作替换。

## 已执行检查与待验证

全部项目Java源码使用本地缓存依赖独立javac通过，未运行Gradle。首版检查覆盖切片三形态／基质NBT往返、未知版本和非法数据拒绝、化石宿主与标本codec。双槽语义修订后重新检查：空中央一次移入1份、已占用禁止补料、成品禁止重切、64份原料连续加工与提取的数量守恒、无效输入／空槽／大数量边界，以及手动反向、同tick／跳步／终点重放拒绝。

尚未启动实际游戏：双人争用、网络延迟、鼠标拖动体验、菜单关闭、漏斗补料／抽料、机器破坏掉落及库存防复制须在注册正式原料后联调。独立规则检查不替代这些世界和容器测试。后续第30条展示柜可直接读取FossilSliceData识别切片，不需要为每个物种另注册切片物品。
