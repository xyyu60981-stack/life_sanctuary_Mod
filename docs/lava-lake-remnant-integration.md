# 岩浆湖岸边炭化／燃尽残材

对应2026-10-27修订第23条。已在FEATURE注册表登记life_sanctuary:lava_lake_remnants类型，具体ConfiguredFeature、PlacedFeature和群系关联尚未提供：正式群系和材料仍待作者接入，不向其他群系添加隐含概率。

## 配置入口

LavaLakeRemnantFeature.Configuration通过CODEC接入数据包，所有字段明确提供，无猜测默认值：biomes（目标群系标签）、substrates（岸边基底标签）、materials（真实炭化／燃尽方块状态与weight），以及horizontal_radius、vertical_radius、lava_radius、minimum_lava_sources、attempts、maximum_placements。

材料表1～16项、权重各1～1000，仅接受已注册CharredMaterialBlock或BurnedMaterialBlock。炭化材料必须lit=false；各轴向／类型由材料表提供，不在生成时冒充未注册原木或植物。整体丰度与炭化／燃尽比例由群系作者的PlacedFeature频率和材料权重决定，当前未选择数值或输出示例假ID。

该特征应接在实际岩浆湖生成之后，以其附近已知位置为origin；不能拿覆盖全群系的普通随机位置当作“岩浆湖后处理”。内部的岩浆源块证据用于复核附近条件，不是扫描全世界寻找岩浆湖的系统。

性能边界：水平候选半径1～16、垂直0～8、近岩浆半径1～4、候选最多16次、单次最多4处且不超过候选数。minimum_lava_sources按候选所在层与下方一层、XZ指定半径内的源岩浆计数；目标空气格与干燥基底本身不计入可能的岩浆最大数量。流动岩浆不替代源块证据。

## 放置规则

origin及每个候选均需命中目标群系标签，且真实群系ID命名空间为life_sanctuary；即便误把原版群系加入标签也不会在其中生成。只写origin所在区块，越界、不可写区域和高度越界候选直接跳过；不为了放残材强制加载邻区块或另找一片区域。

目标须是无流体空气、无方块实体；下方是标签内干燥合法基底，具有完整上支撑面且无方块实体。基底标签应列出实际可用土石等静态地面，不把容器、装置或动态结构纳入。保留植物、水、现有装饰和建筑，不剥掉草或替换湖岸实体方块。

源岩浆的邻格读集有界并缓存；未加载格为UNKNOWN，已知证据不足时跳过，不当空气。若已知源数已满足配置，则不需要读取或加载其余未知格。每个候选最多试一次，失败不无限回退；成功达到上限即结束，不创建活体身份或成长任务。

天然炭化残材初始未燃。生成后请求一次方块scheduled tick，在服务器主线程调用CharredMaterialTimers同步；生成工作线程不直接写SavedData。CharredMaterialBlock放置／移除回调也只在服务器主线程访问计时数据。原版方块tick存储承接卸载前尚未执行的初始化请求。

## 验证边界

全部源码独立javac（开启弃用警告）通过，未运行Gradle或完整游戏。只读规则检查覆盖合法干燥岸边、错误群系提前拒绝、源块数量、流动岩浆不作为源、已有方块／植物、水体与实体保护、未知区块及预算／不可能配置拒绝。

实际Configured／PlacedFeature数据加载、岩浆湖之后的阶段顺序、自然频率、湖岸地形、主线程初始化和不同种子生成效果仍需正式群系与材料接入后验证。
