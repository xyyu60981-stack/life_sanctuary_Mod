# 采集箱放置与物流验收

当前实现：普通箱 27 格，Plus 54 格；物品 ID 不变，改为可放置的方块物品。
放置箱使用原版箱子界面，服务器端槽位限制存入 `collector_contents` 标签物品。
漏斗通过 Container，模组物流通过所有方向的 ItemHandler 能力访问同一库存。
不注册方块实体 ticker。材质目前为木板占位。
放置后的普通箱与 Plus 支持比较器，使用原版容器充满程度算法及各物品堆叠上限，并非仅统计非空格数。常规存取沿用 BlockEntity.setChanged 的邻居通知；批量清空补充存档与信号通知，拆除后通知比较器。没有新增轮询任务。

采集箱物品悬停提供独立内容物预览：普通 9×3，Plus 9×6，保留空槽、物品图标和数量，下方缩小显示空孢子袋/空花粉袋统计。仅 CollectorBlockItem 返回该 TooltipComponent，不修改原版箱子、潜影盒或其他物品。不依赖 EasyShulkerBoxes；参考其客户端提示组件注册方式，自行绘制网格。
客户端使用物品已有组件快照，无服务器 tick、网络查询或递归容器预览。需后续游戏检查不同 GUI 缩放、空箱/满箱、长物品名称，以及同时安装第三方预览模组时是否出现重复提示。

## 交互悬停窗口

生存背包界面的主库存/快捷栏或腿部装备槽内，悬停采集箱 800ms 后发送一次打开请求。鼠标旁显示灰色半透明圆环底与从顶部顺时针填满的白色进度弧，填满后消失；移出、换槽或更换箱子会重置。环形像素预计算，仅客户端绘制，不发进度网络包。服务器验证当前仍为玩家背包菜单、光标空闲、槽位合法且持有单个采集箱，然后切换为专用交互窗口。
窗口普通箱为 176×168 GUI 像素、Plus 为 176×222，接近原版容器布局；装备箱优先将窗口左上角接在来源图标右侧，保留来源图标与连接线，屏幕空间不足时钳制位置。其他背包位置可左右/上下翻转并限制在屏幕内。窗口显示箱内槽位和玩家主库存，不保留可同时操作的原背包菜单。普通右键打开的旧路径保留。

窗口沿用原版容器点击/拖拽/Shift 同步，服务器绑定实际箱子对象、锁定来源槽位；客户端只更新菜单槽位，不写箱子组件。空袋标注读取已同步的网格。鼠标移出窗口及原悬停点后延迟关闭并返回背包；光标有物品时不自动关闭，手动关闭由原版处理光标物品。返回后短暂抑制再次弹出。

范围：生存 InventoryScreen 的 0–35 槽位及腿部槽 37；创造物品栏、其他装备槽、箱子等其他界面仍为只读预览。网络通信仅在请求打开和原版库存操作时发生，静态预览不请求服务器。

待游戏验收：悬停后移动进窗口、左右键分堆/拖拽/Shift、拒绝非法物品、数字键/丢弃锁定箱子、持物时移出窗口、Esc 关闭、返回背包无重复弹出；低分辨率/GUI 缩放、联网延迟、空箱/满箱/Plus，关闭后再次打开及存档重进确认库存守恒。尚未运行游戏验收。

## 打开快捷键

按键设置中提供“生命庇护所 / 打开采集箱”，默认 B，可自行改绑。仅在实际按键时检查库存，顺序为生存背包中悬停箱、腿部装备箱、背包空槽最多箱；空槽相同时按库存槽位先后，这是用户最终确认的规则，取代大纲的“取得时间”。没有箱子时显示动作栏提示。
快捷键与悬停共用请求等待保护，防止一次请求尚未打开时另一入口覆盖窗口模式。窗口打开即解除，未收到响应则两秒后可重新请求。既有 options.txt 中保存的自定义/未绑定按键不会被默认值覆盖，可在按键设置中重置或手动绑定 B。
可从游戏画面或生存背包打开；其他容器界面及光标持物时不切换菜单。快捷键窗口居中、不因鼠标移出关闭；Esc 后回到原游戏画面或背包。服务器仍校验槽位和箱子身份。验收多个箱子的优先级、满箱可打开、无箱提示、Esc 返回、与悬停请求同时发生时不重复开箱，以及自行绑定的按键与整合包冲突情况。

外观约定：采集箱、Plus、后续培养柜采用一格或两格完整方块，不做开盖动画；打开仅播放箱子音效。当前两种采集箱均为一格，培养柜尚未实现。

模拟玩家现可手持空孢子袋采集问荆：无论单袋还是堆叠空袋，产物均进入非主手选中槽位的库存；最后一个空袋消耗后清空交互手。空间不足拒绝采集，不扣袋或额度。普通玩家仍使用采集箱。
不主动搜索附近或多方块结构容器，不直接指定输出容器，交由 Create 自身物流执行。
Create 6.0.10 的 DeployerMovementBehaviour.tryGrabbingItem 从结构 getAllItems 库存按 FilterItemStack.test 取料。FilterItemStack.test 在空过滤器时返回 true，原本会自动取袋。现在通过可选 Mixin 在 lambda$tryGrabbingItem$0 中拒绝空过滤器取空袋；非空过滤器仍须通过 Create 的匹配判断。不追踪已持有袋子的来源，也不拦截手工/漏斗直接供料。
这一钩子仅覆盖移动结构机械手从结构库存取料，未改动其他模组的模拟玩家或额外物流插件。现要求直接设置对应空袋，或普通过滤器白名单直接包含对应空袋。黑名单、属性过滤器、嵌套过滤器不视为显式授权；已装物种的袋子也不算空袋授权。Create 原有匹配仍须通过，不强行允许不匹配的袋子。
ListFilterItem.getFilterItems 在黑名单模式返回空数组，此行为已按 6.0.10 字节码核对；只遍历其直接条目，不递归扫描容器或过滤器。孢子/花粉判断沿用同一个物种标签读取格式。
Mixin 使用字符串目标和 @Pseudo，不添加 Create 强制依赖。配置 required=false，升级 Create 若钩子失配可能跳过并记录错误；因此升级后必须查启动日志并重新验收，不能默认规则仍有效。当前只按用户提供的 6.0.10 字节码核对签名，尚未游戏验证。
用户已确认过滤器允许对应一种空袋即可，无需两种同时存在。
DeployerMovementBehaviour.tryDisposeOfExcess 保留主手选中槽位内符合过滤器的物品，其余交给 collectOrDropItem。因此产物不应放回主手选中槽位。外部结构库存满时最终处理仍由 Create 决定，本模组仅保证模拟玩家库存不足时不执行采集。
花粉采集入口仍待具体可采花粉结构实现，本轮不宣称花粉自动采集已完成。

库存存档使用 Items，携带形式使用 minecraft:container；原版基类在放置时恢复组件。
生存模式通过掉落表复制库存组件，不另外散落内容。创造模式拆除非空箱时生成带库存箱。
手持右键可打开库存，潜行右键方块可放置；植物右键采集优先于物品使用。
机械手等模拟玩家只执行植物交互，不通过物品使用打开界面或放置箱子。
手持界面直接访问物品组件，不在关闭时复制回写；锁定当前箱子所在槽位和对应数字键/副手交换。
普通箱配方按大纲为：玻璃板/皮革/玻璃板，木板/铁锭/木板，木台阶/木台阶/木台阶；取得皮革解锁配方。
普通箱与一颗钻石无序升级 Plus，可用背包 2×2 合成栏。特殊升级配方保留完整组件，不修改输入的预览数据；尚未实现特殊升级配方的配方书展示。
采集箱可拖入腿部槽，或潜行对空右键装备/交换现有腿部装备，沿用原版装备交换与绑定限制；普通右键仍打开库存，潜行右键方块仍放置。装备提供 5 点护甲（铁护腿等值），不设耐久。手持或存放时不提供护甲。
附魔台与铁砧允许保护、火焰保护、爆炸保护、弹射物保护，附魔能力取铁护甲的 9；不接受耐久、经验修补等其他附魔。各保护附魔的互斥仍沿用原版。火焰保护等级大于零时，掉落物拒绝 IS_FIRE 类型伤害（火和岩浆），不影响爆炸等其他伤害或自然消失计时。放置方块的可燃性仍为默认 0。
升级复制完整组件；方块态保留附魔组件，掉落表明确复制附魔，创造拆箱也复制组件。
未实现装备外观及航空学移动结构适配。
首次将普通采集箱或 Plus 装入腿部槽，解锁“植物猎人”进度（位于冒险页）。通过服务端装备变化事件判定，模拟玩家不触发；箱内物品变化不反复检查进度，普通箱换 Plus 也可补获。重新进入世界时原版装备检测会覆盖已穿戴的箱子。验收普通箱/Plus 各自首次装备、重复穿脱不重复弹出、已有装备存档进入以及手持/放置不触发。

## 装备箱自动收纳

`collectorAutoPickup`（默认 true）控制拾取掉落物时优先存入腿部装备的采集箱；`collectorPickupBlacklist` 为物品 ID 黑名单。这是当前公共配置，尚无每玩家独立设置界面。只接收 collector_contents 白名单内的非空袋物品，不吸入空袋，不递归展开容器，不替机械手处理产物。
单次插入先合并同组件物品堆，再用空槽，最后只写一次箱子组件；仅扣减已接收的掉落数量，剩余继续原版背包拾取。箱子/背包均满时剩余掉落保留。沿用拾取延迟、指定拾取者及之前的拾取拒绝结果；对成功转入箱子的部分发送拾取反馈和 Post 事件。其他模组对拾取事件的改写仍需整合包实测。
验收：背包满但箱内有空间、箱内只容纳部分、箱与背包均满、同物种堆合并/不同物种不合并、空袋走背包、黑名单走背包、开关关闭、他人归属掉落、拾取后存档重载。仅碰撞拾取触发，无每 tick 范围扫描。

## 本地验证（尚未在 Codex 中运行）

1. 编译后启动游戏：分别放置普通箱和 Plus，确认 27 / 54 格可打开。
2. 放入空袋、已装孢子袋、种子；尝试普通物品及箱子嵌套，应拒绝。测试普通点击、Shift、数字键和拖拽。
3. 箱子上下连接漏斗，检查白名单过滤、取出和容量上限。
4. 放入有物种标签的袋子后生存拆箱，再放置，检查数量及标签保持；创造拆除非空箱同样检查。
5. 保存退出重进，检查箱内物品；两名玩家同时打开及物流同时运行时检查数量守恒。
6. 机械手持含空孢子袋的箱子采集，拆放前后检查库存和植物额度；箱满时不得消耗空袋和采集额度。
7. 最后测试机械动力物流，以及航空学装配/拆解和保存重载。不能以基础箱子验证替代移动结构验证。
8. 主手和副手分别打开箱子，测试 Shift 转移、拖拽、数字键、F 键、丢弃当前箱子；箱子不得在界面中被移走。关闭重开应保留内容。
9. 机械手采集失败（缺袋、箱满、额度耗尽）时，箱子不得被放置。人工潜行放置后，验证物品界面与方块界面的库存一致。
10. 分别给予机械手 1 个和多个空袋，检查成品进入输出库存，主手不留下成品袋。移动结构内放空袋但过滤器留空，应不自动取袋；过滤器选择空孢子袋后，应恢复自动取袋。空花粉袋同样测试取料，但花粉采集尚待实现。
11. 不装 Create 启动一次；再装 Create 6.0.10 启动并检查 Mixin 报错。新 Mixin 是否实际应用只能由启动与交互验收确认，Java 编译成功不能替代。
12. 移动结构取袋矩阵：直接空孢子袋允许孢子袋；直接空花粉袋允许花粉袋；白名单只有其中一种时只允许该种，两种均列出则均允许。空过滤器、黑名单、属性过滤器、只含已装物种袋子的列表和嵌套列表不得授权空袋取料。上述限制不影响其他物品。
13. 给普通箱命名并装满带物种标签的袋子，与钻石升级；检查结果是 54 格、原 27 格内容/数量/名称保留。只看结果不取走时输入不得变化。检查钻石堆消耗一个、额外杂物/第二颗独立槽位钻石/第二个箱子/Plus 再升级均不匹配。
14. 普通箱/Plus 分别拖入腿部槽、潜行对空装备、与已有护腿交换；验证内容和名称保持，护甲增加 5 点，取下恢复。装备含空袋的箱子后空手采集问荆，产物应进入装备箱；无空袋或无空间不扣额度。模拟玩家不通过物品 use 自动装备箱子。
15. 放置箱后连接比较器：空箱 0、完全堆满 15，中间状态与同容量原版容器对照；通过玩家、漏斗及模组能力存取时信号应更新。清空、拆箱后无残留信号，重新放置库存仍保持。信号表示库存充满程度，不代表某次采集一定能否成功。
16. 附魔台与铁砧分别验证四种保护附魔可用、耐久和修补不可用；铁砧不能绕过原版互斥。火焰保护箱与未附魔箱分别投入火/岩浆对照，升级、放置拆下、保存重进后检查附魔与库存保留。仅静态核对接口，尚未进行这些游戏测试。
