# 地钱实际接入

2026-10-29用户确认life_sanctuary:marchantia_polymorpha为物种、方块及物品ID；已注册真实方块与孢子袋效果，进入创造物品栏。模型及贴图来源见marchantia-model-integration.md。

## 本批规则

- 孢子播种、普通物品种植及扩散均直接生成完整薄毯，不擅自添加幼苗阶段或成长时长。三种blockstate属性控制土／石外观、繁殖状态与雌托数量。
- 薄毯保持1像素碰撞，生殖托不抬高实体碰撞；选择框可覆盖最高3.4像素。仅下方基底改变时检查支撑并切换外观，无横向连接状态、邻接纹理扫描或方块实体。
- 土面标签默认minecraft:dirt，石面默认c:stones、圆石和苔石，均要求完整上表面；其他基底可通过独立标签补充，未继承光藓专属的原木清单。
- 新环境表优先于旧提取大纲：无临水要求，寒冷停止生长／扩散／繁殖生成，干燥和炎热正常。不添加气候枯死。人工建立时缓存一次气候，自然静止不启动检测和自动计时。
- 人工株每28800～48000有效刻尝试产生一个后代；优先四邻同高度，随后尝试上1／下1，且保持16×16区域归属。无合法落点或小群已满后，等待10000～30000有效刻生成生殖托。
- 每次独立人工种植生成一个扩散组，原株与所有后代合计最多5格；后代继承组标识，不各自获得5格新名额。组标识随个体保存，即使原株被破坏也不重置；同区域不同手植组独立计数，不自动合并。这里按用户“形成5格小群”计入原株。
- 自然区域总计4～10格、分1～3簇。自然成员共用16×16区域计数；人工小群与自然区域数量分开。已实现纯布局规划和 Feature 入口，尚未设置群系生成率或启用群系投放，不宣称已自然出现。
- 骨粉60%使活动成年地钱进入繁殖，寒冷／已有生殖托／异常状态不消耗。生成1～2个雌托与固定3个雄托，四套原生加权摆放稳定错位。
- 整格生殖结构只有1次额度。普通玩家通过手持／装备采集箱，模拟玩家可手持空孢子袋；沿用既有库存交换、名单及机械手输出规则。成功产一袋地钱孢子，全部托一起消失；库存拒绝恢复额度，未知副作用冻结，不重复交付。
- 普通破坏无本体，剪刀／精准掉1个普通物品，不保留额度；堆肥60%。活塞／失去基底按薄植物销毁，注销自己的身份。

## 实现边界与验证

复用PlantIndividuals的个体、部件、种群索引和活动区块计时，没有新增逐株每刻搜索或独立SavedData。自然标签使用区域名；人工标签额外保存创始UUID，只表示五格扩散组，不把整个小群误记成一个生物个体。

完整源码独立javac无警告；654项纯分组／保存／上下1格候选检查通过，覆盖自然与两个人工组独立计数、创始株移除后组不重置、预扣额度恢复不换组、保存重载、负坐标及边界。模型与资源JSON检查通过。未运行Gradle或Minecraft，实际铺毯接缝、上下台阶、骨粉和采集循环仍待游戏验证。

已加入可选 Jade 提示：营养／繁殖阶段、自然静止、寒冷暂停、其他暂停、扩散周期／等待生殖托，以及整格剩余采集次数。仅读取已有个体和气候缓存；身份、结构归属或额度不一致时提示需恢复，不修复数据，不刷新群系，不推进计时。位置和繁殖外观不匹配的旧同步数据不展示。

状态检查统一由 `MarchantiaState` 提供，生长回调、骨粉目标、生成生殖托、采集入口与 Jade 共用。校验物种、种群身份、所属结构、成年阶段、显式额度、循环模式、气候缓存及计时范围。没有额度键不能根据可见生殖托推断为1；模式或计时异常阻止操作，不自动重建。自然静止株无需人工气候缓存，仍可按已有额度采集。22项边界检查及完整源码独立编译通过，覆盖缺失额度、外观冲突、非法模式、未知气候、静止计时和两种循环计时边界；未进行游戏验证。

自然生成入口 `life_sanctuary:marchantia_patch` 已注册，配置必须明确提供 `chunk_chance` 与 `reproductive_chance`，没有默认猜值。筛选入口读取 `life_sanctuary:marchantia_biomes` 群系标签；当前未提供 configured/placed feature、群系成员或 biome modifier，因此没有实际世界投放。

布局只使用本区块最多256个合法表面候选，预建每格至多12个相邻台阶关系；每簇连通，簇间不相邻，上下落差最多1格，基底位置限制在同一16×16区域。内存中至多32次有限布局尝试；不重复扫描世界。完整布局检查通过后才写入，写入失败回退已放部分，不遗留不足4格的半群落。生成线程不访问个体 SavedData，延后至服务器 tick 登记自然静止个体和整格额度。

验证：布局2,034项检查通过，覆盖固定种子可重现、输入顺序独立、负坐标、连通与分簇、总量、跨区和重复列拒绝；配置19项检查通过，覆盖必填字段、概率边界、非法值及编解码往返。完整源码独立编译通过；实际世界生成和失败回退仍需游戏验证。

后续待确认自然群系、生成频率和初始繁殖比例，再补投放文件并进行世界联调。培养柜未配置地钱方案；在没有确认相应培育耗时前不虚构瞬时四倍产物。

资源回归检查：`tools/validate_bryophyte_assets.py` 覆盖附着藓、光藓、地钱三套方块和物品模型引用、纹理文件、附着藓四向四变体、16种附着组合与原版攀爬标签。该检查不替代游戏内渲染或交互验证。

## 游戏内只读诊断

管理员可用 `/life_sanctuary liverwort inspect <x> <y> <z>` 查看当前位置。禁止读取未加载区块或世界高度外的位置，结构正在提交或存档处于只读保护时拒绝检查。无登记个体时提示无记录；有记录但方块消失时仍返回记录并标记 `MISSING_BLOCK`，不重新生成方块或删除个体。

输出包括个体 UUID、基底、物种、种群／人工扩散组、来源及建立路径、阶段、可见繁殖状态、目标／经过／剩余刻数、整格采集额度、等待繁殖标记、气候缓存标记、结构登记数量、组内成员数、暂停原因和一致性结果。查询不调用环境刷新、不推进计时、不补额度、不修复记录。`GroupMembers` 为该完整种群标签的计数；人工组不会和同区块其他人工组或自然群落混算。

`Consistency=NONE` 只说明数据结构一致，寒冷等合法暂停仍单独列在 `PauseReasons` 中。`ENVIRONMENT_UNKNOWN` 表示人工气候缓存未就绪；`QUOTA`、`TIMER`、`MODE`、`STRUCTURE` 等表示对应数据冲突，需要结合操作日志排查，不能把可见外观当作补齐额度的依据。

独立编译和16项诊断快照检查通过，覆盖剩余时间、人工组标识、缺失方块与额度冲突的区分、结构缺失、快照修改不会改动原个体。命令权限和世界访问路径仍待游戏内验证。
