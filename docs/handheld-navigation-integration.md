# 掌机APP导航接入与验证边界

第33条已接入实际`life_sanctuary:game_start`物品与客户端掌机界面。名称“Game Start”、初始APP“sfernm”来自当前大纲第14章；未凭空添加演示游戏或把尚未设计的解锁条件写死。物品单件堆叠，已加入本模组创造栏。

## 获得与界面

实际工作台配方沿大纲三行：青金石／玻璃／金锭，铁锭／钻石／铁锭，铁锭／铁锭／铁锭，得到1台。当前物品贴图暂用原版书本作为占位，掌机边框以GUI矩形绘制，最终设备美术可替换。

手持右键空气进入长方边框主界面；对可交互方块使用时仍按原版方块交互优先级处理。物品使用成功但不消耗，不创建服务器游戏会话。客户端RightClickItem事件仅为本地玩家、存活、非旁观、当前无其他界面并持有HandheldItem时打开，公共物品类不引用客户端Screen，专用服务器不会从此物品加载GUI代码。

初始只有sfernm，点击或确认打开其应用壳，当前显示“暂无可用游戏”，返回按钮／Esc回到掌机。没有物品提交槽、不消耗孢子袋、不自动解锁Cooksonia、不伪造关卡、进度或奖励。失去对应手中掌机或死亡时关闭主界面／sfernm；界面不暂停单人世界。

## 键鼠与多页

- W／上：上一行；S／下：下一行。
- A／左、D／右：同一行内移动，边缘不跳到另一行。
- 回车／小键盘回车／空格：打开当前APP；Esc关闭主界面。
- 鼠标移到按钮同步选中状态，点击打开；Tab切换焦点后与键盘选中同步，翻页按钮也保留其确认行为。

HandheldNavigation为纯索引规则，不触碰世界或联网。最后一行不满时向下选最近有效列，空列表返回-1，不存在的按钮不能触发。每页两行，按窗口宽度1～4列；键盘移到另一页自动重建当前页，鼠标可用左右翻页按钮。窗口重新布局保留选中APP，APP注册顺序决定展示顺序；当前仅一个APP，因此多数移动自然停在同一图标。

APP图标只在布局时获取并缓存，渲染不反复创建ItemStack；页面只创建当前可见按钮，没有逐帧网络请求、背包扫描或游戏会话结算。

## 后续APP与小游戏接口

HandheldApps.App包含稳定ID、名称、图标工厂和打开回调，客户端setup时按顺序register；重复ID拒绝，界面使用不可变快照。客户端可添加应用壳或自己实现界面，但此列表没有实现服务器授权的可见性／解锁存档。后续正式解锁必须由服务器验证提交物品、是否消耗及解锁资格，再同步可见APP；当前注册一个图标不等于取得游戏权限。

Cooksonia现有服务端规则、会话身份／版本／冷却检查、生命周期和奖励账本保持不变；本批没有添加游戏动作网络包、正式关卡、棋盘UI、奖励物品交付或80%成就逻辑。正式游戏回调应走已有可信服务器入口，不从本地App.open直接发物品或改进度。
