# 植物商人接入与验证边界

第31条以原版`minecraft:wandering_trader`的持久化变体实现。没有替换游商实体、复制UUID或另写生成调度，原版生成率、游戏规则、位置与空间判定、游荡目标、48000刻离场计时、交易期间暂停离场、夜间隐身／日间喝奶及避敌行为继续使用原版。当前外观沿用原版游商，默认交易名称为“植物商人”；没有新加独立生物ID、刷怪蛋或专用模型。用户后续改名会沿原版保存。

## 生成选择

PlantMerchantSpawns监听服务端FinalizeSpawnEvent，仅处理EVENT来源、实际原版WanderingTrader类与原版实体类型的新游商；命令、刷怪蛋、存档重载及其他模组的游商子类不被自动改写。

- 生成位置群系命名空间为life_sanctuary：100%植物商人。
- 原版minecraft命名空间且属于IS_JUNGLE或IS_SAVANNA标签：30%，按0～99中0～29选择。
- 其他群系：保留普通游商。

身份存入实体原生persistent data的`life_sanctuary:plant_merchant`键，普通游商也记false；不在移动、交易或重载时重抽。不会因玩家站在模组群系而把实际生成在其他群系的游商强行变体化，归属取商人自己的生成位置。尚未注册的本模组群系无需虚构ID，正式接入后按命名空间自动生效。

## 独立交易

用户确认首批两条为：1绿宝石→8空孢子袋；1绿宝石→8空花粉袋。common配置项`plantMerchantBagEmeraldCost`默认1、合法1～64，`plantMerchantBagsPerTrade`默认8、合法1～64，两种空袋当前共用这组配置。配置在新商人生成时读取，已存在商人的价格、售出次数和库存按原版Offers存档保存，不用配置刷新抹掉已售次数。

每条基础交易12次库存、经验1、价格系数0.05，结算、绿宝石扣除和库存耗尽由原版交易菜单完成；没有另写可能重复发货的交互支付逻辑，也不增加重补货。只清理被选中商人自己的getOffers列表并装入新表，不修改VillagerTrades全局列表。AbstractVillager.overrideOffers在服务器NPC中为空实现，不能用它假装换表。

PlantMerchantTrades.register接受稳定交易键和每次返回新MerchantOffer的工厂，用于内容作者补植物产品、带物种组件的繁殖体和第32条指南针。重复键、null或空产物拒绝；装入单个商人时复制offer，避免不同商人共享售出次数。注册应在初始化阶段执行，不从tick或交易回调修改注册表。尚未注册的指南针及未定价植物产品没有虚构条目。

## 无随行羊驼与性能

原版WanderingTraderSpawner在游商spawn调用返回后才生成并牵上羊驼。因此FinalizeSpawnEvent阶段无法凭真实牵引关系直接阻止羊驼创建，盲猜附近游商会误删无关动物。

当前不增加Mixin：只将新EVENT来源的TraderLlama放入一次性队列，在本服务器tick末检查真实getLeashHolder；仅当牵引者是已标记植物商人时，无掉绳、无死亡掉落地解除牵引并discard。普通游商羊驼、玩家牵引者和没有挂到植物商人的羊驼保留；不扫描半径内实体，不按相邻位置猜归属。处理后立即移出队列，关服清空引用，没有持续查找任务或额外世界遍历。

该实现是原版创建附属羊驼后定向移除，不能声称完全跳过了羊驼实例创建；其他模组的生成事件仍可能先看到这些短暂实体，客户端是否可见一瞬需游戏联调。未来若明确需要零创建，可在已核实版本的原版tryToSpawnLlamaFor入口加专用Mixin，保留其他游商路径；目前按用户先完成基础构建的方向不新增该Mixin。

## 已执行检查与待验证

全项目源码使用本地缓存依赖独立javac通过，未运行Gradle；临时规则检查穷举100个随机桶，确认本模组群系100%、原版丛林／稀树草原30%、其他0%，29／30边界及非法随机数拒绝。已阅读原版生成器、游商和AbstractVillager源码，核实原始实体引用、后置牵羊驼、离场计时和实际交易表入口。

尚未启动游戏，不能把概率规则检查当成自然生成及交易验证。待测：原版生成开关／群系位置、植物与普通商人并存、附属羊驼定向移除和普通羊驼保留、两种空袋交易及库存耗尽、不同商人库存隔离、配置对新商人生效、重进后身份／价格／售出次数保持、夜间隐身／交易暂停离场，以及其他改变游商交易或生成的模组联调。
