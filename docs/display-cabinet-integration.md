# 展示柜接入与验证边界

第30条已注册`life_sanctuary:display_cabinet`方块、方块物品、方块实体及客户端展品渲染器。完整1×1×1碰撞方块，玻璃外壳和内部背板均为静态模型；当前使用原版玻璃与平滑石头贴图，最终金店风格材质仍可替换。未擅自添加用户尚未指定的合成配方。

## 摆放与交互

FACING表示观察展品的正面，按放置时点击的表面选择。地面上平放朝上，墙侧放置直立，也支持朝下；完整方块无需墙面支撑。旋转和镜像保持朝向，改朝向不掉展品。

非潜行持物右键空柜：移入1件，保存完整ItemStack组件，包括化石身份、地图ID、附魔、耐久和自定义名称；创造模式按原版展示框习惯复制1件，不消耗手持。满柜不替换或消耗手持物。空手右键取回，优先进背包，余量掉在玩家旁。潜行交互放行，以便在柜上／侧面放方块。冒险模式无建造权限和旁观者不能放取。

破坏、爆炸或被其他方块替换时，从真实方块实体取出展品并掉落；展品先清空，重复移除不会再掉一份。方块loot表仅掉柜体，未把库存另写入方块物品，避免同时复制库存和掉落物。当前没有自动化能力或漏斗容器接口，也没有菜单；用户未指定展示柜须有这些功能。

## 显示接口

DisplayCabinetRenderer使用原生FIXED物品模型展示食物、武器、工具、装备、方块及切片，三维方块按0.55比例放在柜内，静止且不旋转。切片仍使用已有FossilSliceItem及FossilSliceData，不新建重复切片物品。若后续需要不同标本专用的雕刻／印痕细节，内容作者应补切片物品模型或在本渲染器增加专门分支；当前纸贴图不能代表化石美术已完成。

地图使用原版MapRenderer显示128×128画面。客户端已有地图数据时优先使用；否则方块首次区块同步／展品变化时，服务端附带有界地图颜色快照作为后备。初始方块实体尚未设置level时保留快照，第一次渲染再构造客户端地图数据。快照仅用于显示，不存入世界副本，也不推进地图探索。后备快照没有原版完整的动态标记和持续地图更新协议；柜内地图不是自动探索器，其他玩家后来更新地图时不保证实时刷新，取回再放入或重新加载可获取新的服务器快照。

## 性能与验证

没有方块ticker、旋转动画、范围扫描或逐帧网络请求。展品变化才标脏和发送方块更新，区块初次追踪发送当前展品；地图快照仅地图展品需要。空柜渲染器立即返回，非空展示距离32格，沿用原生区块／方块实体视锥裁剪。大量可见展品仍有原生物品模型和地图绘制成本，不能把静态柜体等同于零渲染成本。

全项目Java源码使用本地缓存依赖独立javac通过，未运行Gradle。临时几何检查直接读取blockstate和模型，并对比原版BlockModelRotation与实际展品旋转：六个观察面均一致，玻璃为六面完整外壳，标准一格物品模型缩放后位于柜内。

未启动游戏。需验证客户端／专用服务器加载、六向放置、空手取回／满背包溢出、创造模式、潜行相邻放置、切片组件／附魔工具往返、重进存档、区块初次同步、地图正反／朝向及画面、破坏／爆炸单次掉落，以及光影下的透明外壳观感。独立编译和几何检查不等于这些交互或网络行为已通过游戏测试。
