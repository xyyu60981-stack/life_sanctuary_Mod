# 库克逊蕨找泥炭：公共底座

依据当前工作区大纲“14 庇护所掌机与小游戏”及用户后续规则实现；大纲中的历史写作说明不作为当前操作指令。只固定公共机制，不自行设定关卡、美术、奖励或尚未确认参数。

## 当前实现：地面棋盘

CooksoniaBoard 是纯 Java 不可变正方形地面，不注册物品／APP ID，不读写世界，不启动 tick。坐标 x 向右、y 向下，独立于 Minecraft 的 xyz。构造时由未来关卡生成器明确提供边长和全部地格，缺失、不完整或乘法溢出的大小拒绝；没有自动生成默认地图或随机填充。

地格实际类型为普通、寒冷、干燥、泥炭、圆石、一次水和河流；隐藏是独立可见标记，类型在棋盘创建时已经确定，揭示不抽随机。寒冷与干燥通过互斥地形类型表达。圆石和两种水不允许隐藏。

revealAround 揭示中心及周围 3×3，边界裁剪，重复揭示不改变实际类型。cardinalNeighbors 只返回上下左右，和 3×3 揭示范围明确区分。wet 只湿润调用方明确提供的地格，将干燥永久变普通，保留寒冷、泥炭和原可见性；它不自行规划水路或揭示隐藏地格。

consumePeat 只构造泥炭变普通的地面提案，不单独发分数、行动或分叉。未来操作结算必须将地形、固定 500 分和本株行动＋1／分叉＋1 一起提交，避免重复领取。

## 当前实现：植株资源、头与占位

CooksoniaPlant 记录同株行动／分叉、类型及共享走茎成熟计数、一次产出周期是否完成，头通过 plantId 共享该对象，不在各头复制资源或计数。spendAction／spendBranch／peatBonus／retire 保留成熟历史；retire 将资源归零并永久标记本局失活，禁止用残余分叉或泥炭接口复活。镐和移动落点在最后活头归零时会执行失活及走茎清理。

CooksoniaHead 记录独立生命、坐标及可选四向朝向。孢子新生头的生命由正式关卡参数提供且无初始朝向；分叉头固定一生命。已有朝向不能反向移动，零生命头不能发起新动作；从正生命受伤至零仍可构建本次移动后的头。一秒倒下动画尚未绘制，倒下后的阻挡已按用户确认保持不变。

CooksoniaOccupancy 将 HEAD／STEM／GAMETOPHYTE 占位与地面分开，拒绝越界、同格重叠及同一单位 ID 重复占格；同株各段可以有相同 plantId。坐标与单位 ID 查询使用已有索引，不在查询时扫描所有格子。moveHead 仅在四邻空目标合法时，一次提出头移位和原格留同株走茎，不能覆盖其他走茎；每次成功操作才复制／重建占位索引，不增设真实时间 tick 扫描。

以上模型由下节整局快照统一校验，不能分别写回头、资源和占位后就声称完成一次移动。配子体已有独立记录、单回合进度提案与萌发／枯死处理阶段。移动已有下述只读预检及扣费／泥炭／落点阶段，水路和完整回合顺序仍由后续统一操作层完成。

## 当前实现：整局一致性与配子体记录

CooksoniaGameState 将地面、占位、植株、头、配子体以及全局孢子／等待／镐／分数／回合／已通关标记组合成不可变快照。初始值全部由未来关卡提供，不填默认资源，也不从保存恢复棋盘。构造时检查地图尺寸一致、资源非负、字典键与单位身份一致，双向核对头／配子体坐标及归属，拒绝幽灵占位、无主走茎或重复预留的新植株身份。

每株有活头时必须为非失活状态；无活头时必须已 retire 并清零行动与分叉。按用户最新确认，失活株走茎全部消失，零生命头保留占位和阻挡；根快照拒绝失活株仍占有走茎。具体一秒倒下动画尚未绘制，零生命 HEAD 本身已能阻止其他头或孢子进入。头和所属植株通过索引按需查询，不在查询时遍历整个地面。

producedSpores 单独记录本局走茎累计产量，不与当前孢子库存混用；初始关卡库存不计作走茎生产。所有核心复制路径（破石、移动落点、播种、等待、萌发、通关及播放视图）保留该字段，消费孢子不恢复累计额度。兼容旧初始化构造器从零产量开始；复制已有对局必须使用包含 producedSpores 的完整构造器。可见 Content 同步累计产量与同株进度。

CooksoniaGametophyte 记录独立身份、预留的新植株身份、位置、普通／冻原类型、出生回合、0～2 的成长／缺水回合，以及播种时预留的泥炭加成。整局快照拒绝出生回合位于未来或复用已经存在／预留的植株 ID；原植株与孢子新植株不会因此共享行动。进度与生成头／删除占位已由移动／等待的完整回合统一提交；初始生命、a/b 等仍由后续关卡配置提供。

CooksoniaGametophyteTurns.plan 接收操作开始前的整局快照，以及本次落点／补水之后的地面，只遍历原快照的配子体，不扫描整个棋盘、不读随机源。非干燥时成长加一并清零缺水；干燥时保留成长进度、缺水加一，连续两次干燥进入待枯死集合。未到期前恢复湿润则同次回合恢复成长，不重置已经取得的有效成长回合。成长两回合进入待萌发集合。到期者不再推进，也不会因稍后补水而复活；外层应在该回合内完成到期处理。

Plan 的 nextTurn 严格为原回合加一，绑定原快照及结算后的地面，进度和两种到期 ID 集合均不可变。重复计算同一输入只得到相同进度，不自行累加或执行副作用；真正提交仍需核对旧快照身份。新播种／新生单位不在原快照中，外层随后合入，避免同回合额外成长。此接口只能由移动／等待的统一回合结算调用，不能由真实时间 tick、分叉、播种或镐操作调用。

CooksoniaGermination.finish 接收动作前快照、落点后快照、同源 Plan 和明确的 Parameters；拒绝旧提案、错地面、已推进回合、配子体已被更改或撤销原通关标记。落点后快照必须已经处理动作自身的资源、头及失活，但保留原配子体进度。到期配子体转为同位置、无朝向的新头，单位 ID 延续，独立植株 ID 使用预留的 futurePlantId；普通行动／分叉／生命来自关卡参数，冻原行动减一。若播种时领取过泥炭，萌发时行动／分叉再各加一，生命不变，也不重复加分。不为参数填默认值，冻原所需基行动少于一时报告配置错误，不擅自截为零。

枯死者移除配子体和对应占位；其他配子体保留本回合推进后的进度。占位 changeAll 先检查全部旧值和最终单位 ID，成功后只复制／重建一次索引；任一占位或身份冲突都不发布部分结果。finish 返回经过整局一致性校验的新快照，保留落点阶段已经结算的旧植株资源、头、分数及工具，仅合入新生／枯死及回合号。没有 RNG 或外部写入，不在出生时重复领取播种时已结算的泥炭奖励。它仍是内部回合阶段，调用方需继续完成其他回合机制、通关判定及会话提交，不能直接作为玩家操作入口。

统一操作层必须先构造通过一致性校验的完整新快照，再替换服务器会话中的旧快照；不能将资源、头和占位分别提交。当前已有会话镐／播种／完整等待／普通地面移动／分叉入口；已有显式配置的开局模板／工厂，尚无正式关卡内容、网络或可运行 UI，本轮未运行 Gradle。

## 已有设计、后续实现边界

CooksoniaWait.prepare 只构建等待次数减一的中间快照，不要求有活头或选中某株，不扣行动／分叉／生命，不动地面、孢子或配子体进度，也不增加回合号。没有次数时返回 NO_WAITS 和原快照。后续必须先推进此前已有结构、处理出生／死亡，再做通关／失败判定；不能在次数刚减至零时就把“没有活头”判失败，否则会吞掉最后一次等待带来的新头。

CooksoniaWaitRequest 只含对局 ID 和操作版本，不接受客户端指定推进量或时间。用户已确认走茎计数同株共享、当前成熟只产一次、z 限制累计产量；全头倒下的植株停止成熟并移除走茎，头保持阻挡。具体 y／一次产量／z 数值仍留正式关卡配置，不设置默认值；不同关卡后续若设计其他产出机制，需明确扩展规则，不擅自加入重复生产。

CooksoniaStemMaturation 从动作前 Occupancy 缓存的 stemPlants 取得已有走茎的植株集合，每株每回合只计一次，和走茎格数、活头数无关；新留下的走茎不在动作前集合，本轮不额外成长。原植株成熟字段须尚未推进，失活株或已完成周期跳过。达到 y 后，一次产量受剩余累计 z 限制，同时更新库存和 producedSpores；达到总上限后即使消费孢子也不恢复产量。sporeCycleFinished 表示本次成熟结算已结束，包括被累计上限截断的产出，不表示一定获得了完整数量。只在实际游戏回合调用，无真实 tick 自动成熟。

CooksoniaRetirement 在构建失活快照前批量去掉该株所有 STEM；HEAD 即使生命零也保持原位置与身份，继续阻挡。镐致死和移动致死都调用同一清理，移动刚留下的走茎也会随最后活头死亡而消失；不影响其他活植株的走茎。普通操作不扫描清理层，只有失活时执行；根快照额外拒绝残留失活走茎。成熟进度保留作历史但不再推进，不重新发资源或复活。

CooksoniaTurnResolver.Rules 明确组合新头参数与走茎规则。finish 先使用动作前配子体集合和动作后地面推进，处理出生／枯死及唯一一次回合加一，再对动作前已有走茎执行同株成熟。新植株不额外成熟，新走茎不额外成熟；中间阶段和总产量不匹配时不返回部分结果。Session.waitTurn 先扣一次等待，再执行整个组合，最后判通关／失败、提交版本和 30 tick 冷却。最后一次等待能恰好萌发出头时不会提前全灭；仍未萌发且没有活头／等待时正常结束。未提供整套回合规则时返回 TURN_RULES_REQUIRED，不扣次数，不设置默认参数。

CooksoniaSporePreflight 提供服务器快照／客户端可见 Content 两个入口：必须有存活选中头和全局孢子，目标在以头为中心的 5×5 正方形内、棋盘内且没有头／走茎／配子体。普通、泥炭、寒冷可播，已知干燥、圆石、河流、一次水不可播。隐藏目标按未知地面一律允许，不根据实际隐藏类型改变高亮；客户端与服务器使用同一检查规则。无中间路径检测，可以越过圆石、水和单位；不是四邻或菱形范围。

CooksoniaSporeSowing.sow 合法时仅扣一个全局孢子，生成独立配子体和预留新植株身份，起始成长／缺水均为零，出生回合为当前回合；不扣发射头的生命或原植株行动／分叉，不推进回合。目标及周围 3×3 揭示，隐藏干燥落下后才显现并留给后续回合暂停成长／缺水处理；寒冷目标生成冻原型配子体。目标泥炭立即变普通并加 500 分，行动／分叉奖励记在新配子体的 peatBonus，归未来新植株；回合推进保留该标记，萌发只兑现一次，不给发射植株加资源或再次加分。

播种单位 ID 与 futurePlantId 均由服务器提供；检查当前单位、植株及配子体预留身份，身份冲突或非法落点返回原快照，不扣孢子、不揭示。分数溢出在发布前报错。纯结算现已接入下述会话请求、身份／版本／冷却门控及本局通关事件；尚无真实网络／奖励发放。没有新增物品／APP ID 或填默认关卡值。

CooksoniaSporeRequest 仅携带对局 ID、操作版本、所选头及目标。Session.sowSpore 从真实宿主取得玩家身份，先复用会话门控，再检查落点，合法后才由服务器分配两个 UUID。成功时统一判断严格阈值通关、版本加一、清除旧可见内容缓存并启动 30 tick 冷却；不推进棋盘回合或配子体成长。SporeActionResult 返回拒绝原因、当前版本及本局首次通关标记，不发奖励。镐与播种共用 publish，发布前完成所有可能失败的计算，分数溢出等错误不留部分费用。水流、结束、关闭、错误玩家／会话、旧版本和冷却都能阻止播种；非法目标不启动冷却或刷新缓存。

大纲表格补充明确：河流成群且阻头，四邻不会干燥；孢子落点揭示本格及周围 3×3。用户随后确认一次水由圆石包围，破坏哪一侧圆石就向该方向流出；前方有阻挡时优先右转，前方与右侧均阻挡再左转。最多经过 5 格包含原水格，可穿过头／走茎／配子体且不破坏它们；遇河流停止，润湿已经走过的路径后快速消失，原水格变普通。流动期间不能操作。这些新规则替代此前四项待确认记录。

CooksoniaOneShotWater.plan 接收破石后的地面及明确的水源／被打开的四邻普通出口；对角破石不算出口。路径长度含源格，最多 5 格，按前／右／左规划，圆石和边界阻挡，不后退或循环计算同格；遇河流停止且不把河流变普通。路径及其四邻去重后与原水消失合并为一次地面复制，不揭示隐藏，不消耗泥炭，不改变寒冷。Plan 绑定原地面身份并提供不可变路径，供以后动画使用；完全不读取或改写单位层。

用户补充确认同一圆石打开多个水源时，各水路互不影响；水源本来由阻挡地形包围，触发后流至终点润湿并全部消失，再允许操作。镐现在收集被破石格四邻的本次水源，在同一破石地面上独立规划每条路径，合并湿润范围并一次将全部源点变普通；不把前一水路的结果传给后一条。已触发源点作为本次即将消失的地面，不相互触发／阻挡；未触发源点按地图约束应封闭，若规划仍碰到则 INVALID_SOURCE_LAYOUT，整次破石拒绝并保留原状态，不引入级联规则。

CooksoniaPickaxe 将圆石破坏、工具／行动或生命费用、水路湿润与源点消失组合为同一个不可变新快照。flows 仅为服务器内部 Plan，含原地面，不得发送客户端。所有水路都成功才发布，任一路地图布局无效则不扣费、不破石。不会因水流推进棋盘回合或配子体，不改单位身份／占位。

CooksoniaWaterPlayback 提供只读路径、每格播放／消散时长及剩余服务器 tick，不持有 Plan 或隐藏地面。Timing 必须明确配置，未填时会话对需放水的操作返回 WATER_TIMING_REQUIRED，原状态、费用、版本和冷却不变；普通无水镐操作仍可使用旧构造方式。多路并行按最长路径计播放时长，不将时长相加，不设默认参数。

服务器先算出最终快照；播放期间可见 Content 使用已破石但未湿润／未消失的地面及已扣费资源，叠加只读路径进度。播放结束才切换最终湿润／源点消失的可见 Content。播放器和通用 30 tick 冷却同时推进，任一未结束就不能操作；重复或倒序 tick 不加速，播放 tick 不增加操作版本／棋盘回合。播放结束只重建一次可见内容，逐 tick 只更新轻量播放外壳并复用路径；关闭立即清除播放。实际像素动画绘制、网络传输与真实事件挂接仍未实现。

CooksoniaRiverMoisture 在固定地图初始化时扫描一次，索引全部河流与去重后的四邻，不含斜角。apply 只检查原河流位置并湿润邻格，复用 Board.wet 一次构建地面；干燥转普通，寒冷／泥炭及可见性保留，不消耗泥炭或加分。没有真实 tick 扫描，也不触发回合、单位或资源变更。后续地面沿用固定河流拓扑；若未来新机制新增／移动河流须重建索引，原河流被移除或尺寸改变则拒绝旧索引。当前为内部地面阶段，已接入 CooksoniaLevel 模板初始化；一次水路由破石结算处理。

CooksoniaMoveLanding.prepare 每次自行调用预检，不信任外部 Cost。合法地面移动将头移一格、更新朝向、原格留同株走茎、扣本株行动或当前头生命、叠加寒冷／干燥伤害，并处理中心泥炭 500 分和行动／分叉各加一，组合成经一致性校验的中间快照。走茎 ID 必须由服务器提供且未被其他单位占用，非法预检或重复走茎身份返回原快照。全程不可变，无 RNG 或外部写入。

Board.revealLanding 将中心泥炭变普通和中心周围 3×3 揭示合成一次地面复制；其他泥炭只揭示不消耗，保留湿润状态。普通 revealAround 保持只揭示的原语义。致死移动仍到达目标、揭示及记分；若无同株活头则 retire 清零资源并清除包括刚留下走茎在内的全部本株走茎，有同株活头则保留走茎和共享奖励，其他植株的头不能阻止本株失活。算术溢出在发布前报错，不提交部分状态。

Campaign.start给每个正式玩家Session安装由服务器目录与最新progress决定的工具权限；不把客户端显示或库存数量作为解锁凭证。工具操作在身份／会话／版本／冷却门控后、任何目标结算和扣费前检查权限，锁定返回TOOL_LOCKED，不改资源、揭示、版本或冷却。内部快照镐入口同样检查，不能绕过请求层。直接构造的独立纯测试Session仍可验证全部动作；实际生命周期宿主始终通过Campaign建立带权限会话。

View外壳附带只读enabledTools集合，客户端可以据此显示工具；它不包含工具解锁条件引用的隐藏地面，也不能改变权威权限。当前对局通关后，新权限从最新权威进度推导，不要求退出重开；不会额外推进棋盘回合或增加动作版本。关闭会话清除权限回调，避免外部持有已关闭Session时继续牵住Campaign。
