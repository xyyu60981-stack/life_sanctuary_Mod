# 培养柜基础游戏验证

这些步骤需要用户自行启动开发游戏或安装已打包 mod；Codex 未运行 Gradle 或游戏验证。

## 无物种配方也能验证的项目

1. 创造模式取得“卧式光照培养柜”，或使用 `/give @s life_sanctuary:horizontal_light_cultivation_cabinet`。
2. 放单柜，普通右键应打开两槽界面并播放箱子开启音效，柜体没有开盖动画。
3. 同朝向左右放第二柜，等待一个活动 tick 后，从任一侧右键应打开四槽“大型卧式光照培养柜”。再放第三柜不能成为六槽。
4. 潜行手持普通方块点击上方／侧面，应放置方块，不开界面。普通物品在 UI 内 Shift 点击只在背包和快捷栏间移动。
5. 拆掉一半，另一半应恢复两槽单柜；保存退出重进及跨区块放置，检查有效配对是否恢复。区块未加载不会被诊断命令强制加载。
6. 管理员使用 `/life_sanctuary cultivation inspect x y z` 查询目标。可使用相对坐标，例如站在柜体上时 `/life_sanctuary cultivation inspect ~ ~-1 ~`。命令显示半柜标记、各半柜本地两槽、状态与输出余量；红石仅显示已有缓存，UNKNOWN 不等于无电。状态中的通电／暂停也基于该缓存，不代表命令另做实时供电检查。
7. 当前没有真实物种培育方案，正常满孢子袋应提示未配置并保留原样，不能据此测试完整产物流。诊断命令不会创建假物种、加速任务、填充输出或修复存档。
8. 在柜体上下放漏斗，用柜体侧面的拉杆给柜体供电，检查漏斗 ENABLED 状态仍为 true；不要让拉杆／导线另外直接贴邻漏斗。培养柜设为非红石导体，供电读取和比较器输出仍独立保留。此项先验证漏斗是否被锁，不要求已有培育配方。
9. `/life_sanctuary cultivation recipes` 仅检查注册配置：列出方案、缺失产物映射、各阶段自然／机器耗时范围和未配置方案的已登记物种。当前零方案属于尚未接入，不是柜体故障；命令不自动为所有植物生成方案。

## 物种方案接入后再验证

- 主手／副手直投、鼠标投入及 Shift 投入各一次只扣一袋；空袋、花粉袋、错误标签及未配置物种不接受。
- 单柜两批／大柜四批独立计时；有电运行、断电暂停；最终产物不自动重复生成。
- 顶部漏斗输入、底部漏斗抽取；模拟多次不扣物品、不抽时长；每袋最终总计四份。
- 漏斗取走一件后，UI、重载、拆放后都只剩三件；未取完不能投入下一袋。不可堆叠产物总份数同样正确。
- 中间产物仅玩家在 UI 领取；自动化不能取走。玩家取完中间产物后整批终止。
- 背包满或鼠标无法容纳整批时，领取失败不改变批次。多栈使用 Shift 领取。
- 两侧比较器一致，单柜按 0／8／15，大柜按 0／4／8／12／15，输出余量取完才释放该完成名额。
- 双柜跨区块卸载、结构旋转／镜像及机械动力／航空学移动另行测试；基础编译成功不能证明这些兼容路径已验证。
