# 培养柜基础接口

以制作大纲为设计参考，用户后续说明优先。当前已包含两槽／四槽状态、阶段配方、库存交换与存档基础，并注册柜体方块、物品、实体及菜单／界面，接入服务器红石计时、双柜世界配对、顶部自动输入及下方最终产物输出；真实物种培育配方尚待接入。后文按开发顺序记录，较早“未注册／未连接／未加入菜单／未接能力／缓冲未挂接”描述以本段及最新条目为准。

## 已确认规则

- 单柜两个培育槽，连接大柜四槽，每槽投入一袋孢子；每袋对应四份培育结果。中间阶段转下一阶段保持四份，不再次乘四。
- 有红石信号时工作，断电暂停；不能因重复信号提前成熟或重置已选时长。
- 每段按对应物种自然耗时的 60% 培育，整数不足一刻向上取整。
- 培养柜内的配子体不执行自然环境死亡流程。
- 中间阶段可手工取出，自动化仅抽取最终阶段；最终完成槽数对应比较器 0、4、8、12、15。
- 上方输入、下方输出，侧面按许可槽位处理；不可因柜体信号传导意外锁住外部漏斗。
- 光照等级 10。外观遵循用户后续确认的完整方块、无开盖动画方案；尺寸与方块资源后续实现。
- 肋木的近水五日基础、直接培育、萍类走茎等例外由物种配方显式声明，不编造不存在的配子体或幼苗阶段。

## 当前柜体规则（替代下文历史四槽默认值）

单柜占地一格，名称“卧式光照培养柜”，具有两个培育槽；两个单柜并排连接后为“大型卧式光照培养柜”，合计四槽。合成配方产出单柜；连接后的大型柜不作为独立合成产物。具体合成材料及方块连接实现尚未接入。柜体维持完整方块、无开盖动画的既定规则。

CultivationSlots.empty 默认创建两槽，可显式创建四槽。控制器、领取及计时均按实际容量处理；比较器按完成比例输出，单柜为 0／8／15，大柜保持 0／4／8／12／15。每袋四份、阶段耗时 60%、光照 10 和手工／自动领取规则继续适用。

整体存档升为 V2，明确保存 Capacity，仅接受两槽或四槽；V1 始终按原四槽读取，不把旧柜截成两槽。损坏记录、未知版本继续保留原始 NBT，不默认清空。单批次格式仍为 V1。

CultivationCabinetConnection.join／split 仅生成连接和拆分的不可变状态提案。连接保留两侧原槽顺序，大柜前两槽归第一侧、后两槽归第二侧；拆分按此规则恢复，批次 ID、配方、进度和已选时长均保持不变。拒绝重复批次 UUID、不可读状态及不符合容量的输入。尚未加入方块连接事务，调用者未来必须核对并锁定两侧、提交新状态并注销原状态，避免同一批次同时留在单柜和大柜。拆除掉落策略尚未实现。

CultivationCabinetPairing 以坐标、水平朝向和 SINGLE／FIRST／SECOND 快照判定连接。仅同朝向、同高度、左右相邻的两个单柜可配对；前后、上下、斜向、不同朝向或已连接柜均拒绝。FIRST 到 SECOND 固定为朝向的顺时针侧，前两槽归 FIRST、后两槽归 SECOND，与函数参数和区块加载顺序无关。existing 要求两侧相互指向且朝向一致；不能只凭一侧配对标记认领邻柜。

partnerPos 仅计算坐标，不加载区块；邻柜未加载时未来方块接入须暂停连接判定，不据缺失快照直接拆分。几何规则仍不修改方块、批次或控制器，实际放置时若两侧都有候选柜，调用方还需选择其中一个并原子提交，不能同时连接两侧。未加入真实 BlockState 属性或邻居更新回调，未运行 Gradle。

位置与内容联合接口：CultivationCabinetConnection.join(halfA, dataA, halfB, dataB) 自动按 FIRST／SECOND 排序，传参颠倒也返回相同 Joined 提案。Joined.matches 供未来提交前复核，比较两侧几何及全部批次快照；其间发生计时、投入或领取，旧提案便不再匹配。带 Joined 预期值的 split 同时核对当前双向配对和完整四槽内容，再返回带各自坐标的两个单柜提案。拒绝旧内容或错误邻柜，不靠参数顺序分配植物。上述接口仍只生成／验证提案，不会锁定方块、停用旧控制器或提交世界修改；实际连接事务尚待接入。未运行 Gradle。

## 当前代码

### 培育槽物种名称

菜单预览副本添加仅供显示的 CUSTOM_DATA.CultivationPreviewSpecies，界面据此显示物种名称。真实输入袋、产物模板和输出缓冲不写入该显示字段；服务器不读取它来决定消耗、物种或产物。不能把预览作为另一份库存领取。

物种语言键为 `species.<namespace>.<species_path>`，已提供问荆名称。后续作者可通过语言资源补充名称，无需修改菜单逻辑；未提供翻译时回退完整物种 ID，防止不同命名空间的同名物种混淆。字段随既有预览差量同步，只在批次／阶段／产物变化时重建，不增加每 tick 全量标签发送。本轮未运行 Gradle 或游戏界面验证。

### 培育方案配置诊断

`/life_sanctuary cultivation recipes` 以管理员权限按需列出当前方案及其就绪数量、各方案物种／阶段、缺失逻辑产物 ID、自然耗时范围和换算后的机器耗时范围。按物种 ID 排序便于复核；另外列出已登记但没有培育方案的物种，仅表示未配置，不自动认定这些物种都必须支持培育。

查询使用不可变注册快照，不抽取具体时长、不创建 ItemStack、不改配方或补默认方案。它核对的是当前配置，不覆盖已经投入批次保存的旧配方快照；历史批次另用 inspect 查询。本轮未运行 Gradle 或命令游戏验证。

### 运行供电不经柜体锁住漏斗

CultivationCabinetBlock 构造时明确 isRedstoneConductor=false。柜体仍是完整碰撞方块并使用静态完整模型，但不将启动信号作为普通实心导体传给上下漏斗；hasNeighborSignal 的供电读取、两半柜共享启动条件以及独立比较器完成信号继续保留。若外部导线／拉杆直接向漏斗供电，漏斗仍遵守原版被锁规则，柜体不会绕过它。

规则已核对本地 SignalGetter 和 HopperBlock 源码，实际上下漏斗＋侧面拉杆布线测试见 cultivation-verification.md；本轮未运行 Gradle 或游戏验证。

### 只读诊断命令

管理员权限等级 2 的 `/life_sanctuary cultivation inspect <pos>` 查询当前维度已加载位置，显示名称／朝向／半柜标记、双方本地槽状态、当前阶段剩余 tick、已有产物余量及整柜比较器强度。目标未加载时拒绝，不强制读区块；读取现有红石缓存，不用诊断操作触发实时红石扫描。UNKNOWN 表示缓存尚未刷新，不当作已确认断电。

查询不生成物品、不推进／加速计时、不重抽时长或自动修复数据。具体操作步骤见 cultivation-verification.md；配方尚未接入时只能先验证空柜 UI、配对与保护路径。本轮未运行 Gradle 或游戏命令验证。

### 结构旋转／镜像与邻居复核

CultivationCabinetBlock 现实现原版方块旋转与镜像入口：旋转只改变水平朝向，保留半柜标记；非 NONE 镜像同时改变朝向并交换 FIRST／SECOND，SINGLE 保持单柜。这样反射后的相邻坐标仍符合既定顺时针配对规则。物品、培育任务和输出余量不在这些纯方块状态转换函数中搬移；它们继续归所属半柜实体。该规则已与本地 NeoForge 原版箱子的镜像修正源码核对，不代表机械动力或航空学移动结构已联调。

邻居变化始终令红石缓存失效，但仅在可能影响配对的位置安排方块复核：单柜的左右两侧，或已配对柜的另一半所在格。顶部、底部、前后红石变化不再无条件排队检查配对；加载后的首次复核仍保留。方块放置回调发现朝向或半柜标记变化时也安排复核。未运行 Gradle 或结构模板游戏验证。

### UI 阶段与余量说明

菜单增加当前阶段序号／总阶段数和实际剩余产物数的差量同步。悬停显示预览物品名、工作状态、阶段及进度百分比；已有可领取中间产物按当前规则显示四份，自动输出缓冲则显示真实余量。不可堆叠产物即使预览只显示一件，提示仍显示整批剩余份数，并提示多栈用 Shift 交付背包。异常冻结的实物余量仍可查看，但不提示可以领取。

这些字段仅供显示，不控制成熟、抽取或产量；客户端不根据数字生成物品。阶段序号显示限制在菜单短整型范围，不改原配方数据；正常物种阶段不受影响。当前阶段进度仍用千分比量化，未每 tick 发送完整任务。未运行 Gradle 或实际界面验证。

### 输出缓冲与下方自动化（当前已接入）

CultivationCabinetOutputHandler 已注册 Direction.DOWN；顶部仍只输入，侧面和无方向查询暂不提供能力。单柜／大柜分别提供 8／16 个输出实物槽，每个培育名额固定四个实物槽，支持不可堆叠产物。自动化仅能取得最终成熟产物，不抽取中间阶段。getStackInSlot 和 simulate=true 只返回副本，不物化批次、不初始化控制器或推进随机数。

首次真实抽取先构建完整四份产物，核对原任务并在服务器同步步骤中清除该培育批次，将抽取后的剩余实物写入对应输出组；一次取完四份则直接清空该组。后续抽取仅扣减已存实物，绝不重新映射／生成四份。每次抽取后统一标记保存；没有保证调用方外部库存与本柜存档跨文件的崩溃原子性。

输出批次保存原完成任务快照用于界面／名额身份，但不作为第二个活动任务调度。localSlots 将待取输出投影为占用名额，故缓冲没取完不能接新袋；原控制器内该任务已经清除。比较器在仍有可取余量时继续统计该完成名额，最后一件取完才降低。任务与输出同占一个名额、重复批次身份或不可读输出数据令访问不可用，不覆盖原数据。

UI 预览与状态查询显示真实余量，Shift 领取或鼠标领取按剩余实物交付，不补回已自动取走的部分。Output.deliverStored 为既有剩余实物提供独立交付入口，旧适配器默认拒绝；容器／鼠标适配器已实现。若外部交付抛错，保留并冻结输出批次，禁止未知结果再次领取。整柜路由同时记录输出状态身份，余量变化也会使旧操作快照失效。

柜体保存外层 CabinetVersion=1、Cultivation 与 Outputs；物品携带相同结构，拆除／重放保留余量。真正旧格式（无 CabinetVersion 且无 Outputs）明确升级为空输出组，不将新版缺失字段默认为空。输出批次子格式升为 V2，保存完整原任务、Failed 标记和剩余实物；此前仅定义而未接入世界的 V1 缺少原任务快照，读取保留为只读原 NBT，不猜测补齐。两组外层输出格式仍为 V1，培育槽整体仍为 V2。

真实物种配方及产物映射仍未注册，因此目前无法通过正常袋子投入完成实际产物流测试；代码已接入，后续物种配置后需验证模拟多次、单件漏斗抽取、UI 接取剩余、拆放重载、双柜跨区块及满箱拒绝等路径。本轮只做静态检查，未运行 Gradle、保存重进或机械动力联调。

### 每半柜两组输出占位

CultivationOutputSlots 为每半柜保存两组输出批次或不可读占位。deposit 必须与清除原培育批次共同提交，仅接受同一批次 UUID、相同最终产物身份及完整四份实物，不覆盖已有余量，不重复登记批次。后续柜体接入须同时检查培育槽和对应输出组，余量未取完不能接收新袋。

extract 按当前不可变批次对象核对预期状态，旧对象即使 UUID 相同也拒绝重复抽取；只返回剩余状态和实际取得物品的提案，原对象不变。最后一件取完才清空对应输出组。任一子批次不可读时整个输出缓冲只读，不把 unknown 当作空名额。

CultivationOutputSlotsCodec 独立 V1 明确记录两个索引及 Occupied 标记，拒绝缺失／重复／越界索引、异常占用值、空组携带批次及重复批次身份；外层结构或子批次损坏分别保留原 NBT。尚未挂入方块实体、输入占位判断、菜单领取或下方能力，不能据纯提案直接生成输出；后续接入必须统一处理保存及批次转存。未运行 Gradle。

### 自动输出的剩余实物模型与存档

CultivationOutputBatch 为最终成熟批次构建四份实物的不可变提案，继承原批次 UUID 和最终产物身份。每批最多四个固定物品槽，支持一栈四份、按堆叠上限拆栈及四个不可堆叠物品。所有非空栈必须为同物品同组件，总余量为 1～4；对外返回防御副本。extract 仅构建取走指定数量和剩余批次的提案，最后一件取完后 after 为空，其余槽号不移动；模拟不写回就不消费。

独立 CultivationOutputBatchCodec V1 保存原身份、物种／阶段／逻辑产物标识及四个显式槽位的剩余 ItemStack／组件。读取不查询产物映射、不补回四份；错误版本、重复／缺失索引、坏物品、数量异常、物品组件不一致或空的占用批次均保留原 NBT 为只读 Preserved，不能恢复为空槽。物品读取需要当前注册表，已卸载物品无法解析时同样保留原存档。未进行运行时 NBT 往返测试。

本轮只完成模型和编解码，还未给方块实体加入输出缓冲、转存事务或下方 ItemHandler。prepare 成功不等于已经转存；后续必须将输出缓冲写入与原培育批次清除共同提交，并在余量取完前保留对应名额。否则不能直接反复按 prepare 生成物品。顶部输入继续按现有两槽／四槽规则运行，未运行 Gradle。

### 顶部自动输入能力

CultivationCabinetInputHandler 已通过 NeoForge ItemHandler 方块能力注册，仅 Direction.UP 提供入口；底部、侧面及无方向查询暂不提供能力。单柜对应两槽，连接后从任一半柜顶部可路由整柜四槽；每个入口名额一次接收一袋满孢子袋，批次占槽、配置缺失、配对不可用或旧实体引用均返回原输入。

simulate=true 只核对当前快照、配方和名额，返回一袋接收后的余量，不分配批次 UUID、不抽时长、不写存档。真实插入走既有整柜路由及控制器，以 IItemHandler 返回余量确认转移，源容器由调用者按余量更新；不修改传入 ItemStack。getStackInSlot 恒为空，因为此能力代表立即消费的投入通道，不是培育批次第二份物品库存；extractItem 恒为空，不泄露中间产物或袋子。

实体加载、配对连接／拆分时通知能力缓存失效；每次方法调用仍重新核对原实体及当前配对，卸载或失效时不强加载区块，返回零入口／不接受物品。跨线程调用按不可用处理。手工、UI 和自动化统一使用 CultivationRecipes.forSporeBag 解析物种标签，配置就绪检查保持原规则。

目前实际物种方案仍未注册，漏斗接入后现有袋子会保持原样；下方最终产物自动输出、真实物种配置和合成材料待后续接入。本轮未运行 Gradle，也未进行漏斗／机械动力游戏联调。

### 空闲运行与菜单预览优化

服务器 ticker 先检查本地两槽是否存在需要推进的批次；空柜、全部最终完成或全部异常冻结时，跳过邻柜查询、红石检查和控制器创建。配对几何修复仍由放置／邻居／加载安排的方块 tick 执行，不因无培育任务停止。比较器通知前只计算一次新的本地强度。

菜单按批次 ID、不可变配方、阶段、成熟／冻结状态及可领取产物映射缓存预览键。单纯 elapsedTicks 前进不重建 ItemStack／孢子标签，阶段或映射实际变化时才刷新预览；量化进度和电源状态仍正常更新。普通物品 Shift 点击在玩家背包和快捷栏之间移动，满孢子袋仍每次只尝试向培养柜投入一袋，未配置袋子保留原位并提示。没有基准测试数值，不据静态检查宣称具体性能提升幅度；未运行 Gradle。

### 两槽／四槽 UI 与手工操作（当前实现）

潜行右键采用箱子式旁路：柜体的 useItemOn 返回 SKIP_DEFAULT_BLOCK_INTERACTION，useWithoutItem 返回 PASS，不开 UI、不直投、不取物，让原版继续执行手持方块在柜体顶部或侧面放置等物品使用逻辑。服务器交互辅助入口也检查 secondary use，避免额外调用绕过此规则。非潜行时按下述直投／开 UI 规则执行。玩家手工取出培育内容只能在 UI 内进行，不添加潜行右键直接取物；自动化能力仍按独立的最终产物规则后续接入。

手持满孢子袋、整柜有空槽且未打开其他菜单时右键，直接投入一袋；整柜无空槽时改为打开 UI。未持满孢子袋右键也打开 UI。主手为空且副手持满孢子袋时支持副手直投。假玩家不打开 UI；其袋子交互仍走原有投入事务。开柜播放箱子开启音效，没有方块开盖动画。

### 两槽／四槽只读状态查询

CultivationStatus.inspect 在控制器所属服务器线程按需生成状态快照，供未来菜单或 Jade 使用。包含实际容量、通电状态、只读／事务中标记、比较器强度及逐槽物种、批次 ID、阶段顺序、固定目标／已用 tick、缺失产物映射。状态区分空槽、培育中、断电暂停、等待转段、最终完成、映射缺失、异常冻结和数据不可读。

手工／自动可领取产物分别沿用批次规则，且要求产物映射存在；断电不阻止领取已有产物。事务期间、冻结批次、任一不可读槽令整机只读时不提供可领取产物。查询不代表目标背包／容器已有空间，领取仍须重新核对完整快照及执行整批交付。整体 NBT 不可读时容量返回 0，表示未知而非空机器，不默认补两槽。只读查询不生成 ItemStack、不读世界、不抽随机、不修改状态；未实际接入菜单、网络同步或 Jade，未运行 Gradle。

`CultivationRules` 集中四槽、每袋四份、光照及比较器规则。`durationFromNatural` 使用整数计算 3/5，避免长整型乘法溢出及浮点误差。

`CultivationProgress` 保存当前培育阶段、固定目标时长、已用活动 tick 和异常冻结标记。`start` 接受物种已选定的一次自然时长；`advance` 只累计机器调度明确提供的活动 tick，断电或异常不推进，最多到达当前阶段终点。它不会据世界时间、睡觉、卸载或离线自动补算。

`ready` 不表示物品已经产出。到期后必须由未来库存事务确认输入身份、目标槽位和物品交换，再推进阶段；轮询不能自行重复领取产物。`permits` 仅用于相同阶段的普通进度更新，拒绝目标重抽、进度倒退和失败解冻，不能代替阶段转换事务。

## 显式培育配方与注册

CultivationRecipe 保存配方 ID、物种 ID 和有序 Phase 列表。Phase 的 key 为稳定培育阶段键，output 为逻辑产物标识，实际 ItemStack 由后续适配器映射；不要求植物世界中存在相同名称的阶段。不存在的配子体或幼苗不要加入配方。

每段明确自然耗时范围，Phase.start 在输入／产物事务确认可开始时选择一次自然时长，再转换为 60% 机器时长。固定时长不抽随机，重复轮询不得重新调用 start。Phase.accepts 只检查已选目标和阶段是否符合该段范围，不代表库存内容或物品副作用已被验证。未知阶段不能被当作最终阶段；阶段链不接受重复键。

CultivationRecipes 在物种元数据之后配置，一个物种一个方案，配方 ID 与物种重复均拒绝。缺失配方不猜测。各段 outputCount 恒为四；中间转最终仍是四，不是十六。肋木五日基础等例外需在对应配方显式给出，当前没有注册任何真实物种配方。

尚未实现配方快照随在制任务保存、逻辑产物到真实物品映射、单槽／四槽库存事务或热重载；不能将此注册表理解为已可在游戏培育。
## 单槽批次模型

CultivationBatch 保存单袋独立 UUID、完整不可变配方快照、当前阶段下标及固定进度。阶段必须与配方内对应键／时长范围一致；同阶段普通更新不能改变身份或配方，不能跳阶段、倒退进度或解除失败。配方快照当前只在内存模型中保留，NBT 编解码尚未实现。

advance 只推进当前段，到期不会自动出货或连跳下一段；nextPhase 仅在中间段成熟时生成下一段状态提案，保留同一批次和配方。实际调用必须在转换事务确认条件后进行，并用预期批次核对提交，不能重复轮询旧快照反复抽时长。异常冻结不改变已有时长／进度，也不自动恢复。

manualProduct 在当前段成熟时描述当前产物；下一段尚未成熟时仍描述上一段四份中间产物，供手工取出并终止整批。首段尚未成熟没有中间产物。automatedProduct 仅在最终成熟时返回，失败冻结批次两者均不可取。查询返回逻辑产物，不生成 ItemStack；未来领取事务必须一起移除批次，防止重复领取。初始袋子的退回／取消策略尚未实现。
## 单槽批次存档接口

CultivationBatchCodec 使用独立 V1 格式保存批次 UUID、完整配方及有序阶段链、当前下标、已选目标时长、活动进度和异常标记。读取不访问实时配方注册表，不抽取新目标、不推进时钟、不启动机器任务；因此不会因新默认配方覆盖已经投入的批次。

Loaded 提供通过校验的不可变批次；Preserved 保留不支持或损坏的原始 NBT 副本及诊断原因，不可当作空槽重新投入。Preserved.data 每次返回副本，write(ReadResult) 对此结果原样写回，不将未知数据转为空或补默认值。字段类型、阶段链重复键、下标范围、当前阶段键／目标区间、进度越界及非 0/1 失败字节均校验。

未知物种／产物标识可作为字符串恢复到配方快照，不自动绑定当前默认配方；未来机器执行前还必须检查对应物种／产物适配器是否可用。当前未接入方块实体或四槽容器，不能据此宣称已有游戏保存重载功能。未进行运行时 NBT 往返验证；本轮仅静态核对读写字段及差异，未运行 Gradle。
## 四槽状态与提案

CultivationSlots 严格保存四个可选槽，每槽为空、Loaded 批次或不可读 Preserved 数据。同一批次 UUID 不能出现在两个已读槽。任一槽不可读时整机只读，不能投入、推进、领取或根据缺失 batchAt 认定为空；投入判断必须使用 canInsertAt。冻结的可读批次保持占槽。

insert 仅接收首段零进度且未失败的新批次；updateProgress 核对预期旧批次并只允许同段普通推进／冻结；continueBatch 只接收当前中间段成熟后的一段前进，保持批次和配方、新段零进度。所有接口返回不可变状态提案，不消费输入。

extract 同样要求预期批次，按手工／自动规则返回 Extraction（四份逻辑产物和清空该槽后的 after 状态）。调用方必须比较完整旧四槽快照，将 after 与真实物品交换一起提交；同一旧快照多次查询不会自动消除批次，因此不能在没有事务的情况下直接按结果发物品。模拟抽取仅查询，不能写回 after。容量不足、库存未知副作用及重入锁由后续真实库存事务解决。

比较器仅统计最终 ready 批次，按 0／4／8／12／15 输出；不可读整机返回零，中间产物不计完成。当前没有方块实体或物品能力实际调用，没有新增 tick，未运行 Gradle。
## 四槽整体存档格式

CultivationSlotsCodec 使用独立 V1 格式，固定四条显式槽记录，保存 Slot 编号、Occupied 标记及占用时的 Batch。读取按编号还原而非依赖列表排列；槽数量不足、索引越界／重复、错误类型、非 0/1 占用标记，以及空槽携带 Batch 均拒绝，不将缺失槽静默补空。

单个批次不可读时，其原 NBT 留在该槽并使 CultivationSlots 只读；整体容器结构错误或不同可读槽重复批次 UUID 时，整个原容器 NBT 转为 Preserved。两级 Preserved 都可原样写回，读取和返回的数据均作防御复制，不覆盖为默认空状态。外层 Loaded 仍须检查 state.isReadOnly，不能据 Loaded 就允许机器工作。

新方块创建时应明确初始化 CultivationSlots.empty；已有保存字段缺失或损坏不能调用 empty 作为恢复兜底。当前只是编解码接口，尚未挂接方块实体、能力或菜单；未进行游戏保存重进验证，未运行 Gradle。
## 事务控制器与库存边界

CultivationController 由未来服务器方块实体持有，在创建线程上使用。它保存外层 ReadResult，所有变更核对完整预期四槽快照；不可读、旧快照、无效槽或事务重入均拒绝。snapshot 在库存回调期间仍为提交前状态，不暴露半写入提案。CHANGED／RECOVERY_REQUIRED 返回后，方块实体必须标记保存及同步；当前没有方块实体实际持有控制器。

start 检查空槽、新批次身份与注册配方，构造首段提案后调用 Input.consumeOneSporeBag。true 才提交新批次；false 必须表示库存完全未变，保留原槽。若适配器抛错，可能已消费输入，因此保留新批次并冻结，既不重试扣袋也不自动退款。批次 ID 应由每次真实新投入生成，不复用历史 ID。

extract 同时准备清槽及完整四份产物，调用 Output.deliver；true 后提交清槽，false 保留原状态。抛错则冻结原批次并继续占槽，阻止未知出货结果再次领取。两个适配器都必须自行提供原子库存交换，不能部分写入后返回 false；这里不能替第三方库存回滚物品。模拟插入／抽取应使用不可变提案检查，不能将模拟返回 true 传入控制器作为真实成功。

advance 只提交同段活动进度；continueBatch 只在中间段成熟时选取并提交下一段，库存回调期间同样不能重入。控制器自身不调度 tick、不检查真实红石，也不绑定 ItemStack 或逻辑产物映射。未来机器调度仍需在有电、区块活动且处理器可用时调用；没有跨区块存档／外部库存的崩溃原子性保证。未运行 Gradle。
## 满孢子袋输入适配

CultivationSporeBagInput 实现可信 Input 边界，从调用方明确指定的 Container 槽消费一袋。创建时保存完整 ItemStack 副本；执行前要求现存数量和物品／组件仍与快照相同，并确认是满孢子袋及对应物种。空孢子袋、花粉袋、其他物种均不消费。标签兼容本 mod 旧无命名空间物种名及完整 ID，外部命名空间不按 path 混同。

removeItem 后严格检查返回恰好一个原物品，以及源槽恰好剩余原数量减一，再标记来源容器变化。修改前条件不满足返回 false；开始修改后的异常结果必须抛错，交由控制器冻结新批次，不把可能已扣物品的情况当成普通拒绝。Container 若有其他第三方副作用，不能由此接口保证回滚。

此适配器不搜索背包／相邻容器，也不自行决定可访问的侧面。调用者必须先校验手工访问权限或自动化侧面抽取许可。尚未有培养柜方块、菜单或能力调用该适配器，未运行 Gradle。

## 实际产物映射

CultivationProducts 在配置期按物种 ID 与逻辑 output ID 注册一份真实 ItemStack 模板，保留完整组件，拒绝空栈、非单份模板、未知物种和重复覆盖。注册保存副本，不暴露内部模板；同一 output 可在不同物种下映射为各自物品。不同阶段如需不同产物，应声明不同 output ID。

resolve 每次创建独立副本，总数量严格取批次规定的四份，按实际物品堆叠上限拆分；不可堆叠物品返回四栈。缺失映射返回 empty，不猜默认产物，不修改批次、库存或进度。实际 Output 适配器仍须检查整批容量并完成原子交付，不能将 resolve 成功视为已经领取。当前未注册真实物种映射，也未接入方块实体；本轮未运行 Gradle。

## 指定容器整批交付

CultivationContainerOutput 保存明确授权槽位的完整快照，拒绝重复或越界槽位。交付前核对快照，映射完整四份产物，先合并同物品同组件的栈，再按授权槽位顺序使用空槽，同时遵守 Container.canPlaceItem、容器与物品堆叠上限。容量不足或缺失映射返回 false，保留原库存和培养批次。

容量提案只操作副本；调用外部槽位检查后再次核对快照。开始真实写入后，每次写入以及 setChanged 后核对所有授权槽，异常抛给控制器冻结原批次，禁止未知结果再次领取。不尝试回滚第三方副作用，也不保证跨存档崩溃原子性。适配器阻止自身重入；调用方必须在服务器线程使用，并预先校验访问权限和自动化侧面，不将带有未授权副作用的任意 Container 当作可信库存。此接口尚未绑定实际培养柜、菜单或自动化能力，未运行 Gradle。

## 开工与阶段映射检查

控制器 start 在抽取阶段时长及调用扣袋接口之前，要求配方所有阶段的物种／产物映射均已就绪。任一缺失便拒绝开工，不消费袋子、不占槽。CultivationProducts.missingOutputs 按阶段顺序返回去重后的缺失逻辑产物 ID，供未来界面诊断；isReady／isAvailable 只查注册状态，不创建物品栈或判断库存容量。

载入的既有批次继续使用自身配方快照，不强行套用当前默认配方。当前段映射缺失时 advance 保留进度，下一段映射缺失时 continueBatch 拒绝转换，均不重新抽时长、不标记异常冻结；配置补齐后可按原进度继续。映射检查不要求目标容器提前腾出空间，最终交付时才执行整批容量检查。当前没有真实物种配方／产物注册，未来接入必须同时配置两者；未运行 Gradle。

## 四槽活动 tick 入口

CultivationController.tick(powered, random) 为未来服务器方块实体提供单次活动 tick 入口。每个有效调用最多扫描固定四槽；断电直接返回，空槽、失败冻结批次及最终成熟批次不推进。任一不可读数据使整机拒绝运行。各槽独立累计一 tick，中间段成熟后自动尝试前进一段，新段从零开始，不重复计算该 tick；每段时长只在实际转换时抽取一次。

缺失映射时沿用现有暂停／拒绝转换规则，不影响其他有效槽。最终产物保留到领取事务执行，运行入口不自动出货、不自动补袋。返回 CHANGED 时未来方块实体须标记保存，并按需更新菜单／比较器；无需每 tick 写 NBT 或发送全量同步包。调用方必须保证每个服务器活动 tick 至多调用一次，区块卸载及离线时不调用、不按世界时间差补算；不再同时为这些槽调用额外 advance。当前尚未注册实际方块实体 ticker，因此此接口未开始在游戏中运行；未运行 Gradle。
