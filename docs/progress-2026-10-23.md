## 数据与性能

- PlantIndividuals 当前存档版本为 V12；独立叶数据保存阶段允许方向，旧数据不自动生成叶片或补发额度。
- 地下系统、单槽培育批次与四槽容器分别使用自己的版本化格式；未知或损坏数据保留原 NBT，不静默重开空槽。
- 使用现有结构归属、种群与活叶派生索引；叶计时按活动区块与到期队列处理，不逐 tick 扫描全部历史叶。
- STATIC 自然植株一次生成；不会因此启动常规生长、补叶或环境轮询。自然生成失败不降高重试。
- 叶模板、拼装和空间校验按准备生成／阶段变化触发，不增加逐株动态渲染或后台扫描。

## 已确认的关键边界

- 孢子／种子采集仅限完全成年。成年后补叶继续遵循原可育判定与保留额度继承，不能靠换冠刷新次数。
- 五叶方向不等于四个水平 Direction；实际角度和几何由模型提供。若同一交互格包含两片叶，仍需格内命中解析或调整模型占位。
- 亚成体叶形通常与成年体相近、尺寸较小；视觉大小与实际占位分别配置，采集资格独立于模型。
- 培养柜不虚构物种中间阶段，四份中间产物转下一段仍是四份。库存结果不确定时冻结批次，不自动退款或重复出货。

## 验证情况

用户在本地 PowerShell 逐步执行 compileJava 并反馈成功，包括最后的满孢子袋输入适配。期间修复 PlantHarvestEligibility 多写一次 leaves() 导致的编译错误，修复后用户确认成功。

本会话没有运行 Gradle；归档前仅检查代码、接口引用和 Git 差异。编译通过不代表游戏逻辑、存档往返、渲染性能或其他模组兼容已验证。
