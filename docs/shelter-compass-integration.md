# 庇护所指南针接入与验证边界

第32条用户已确认：普通版与天窗版分别定位两类庇护所，普通版不包含天窗；普通指南针、1钻石、1绿宝石无序合成1天窗指南针。

## 物品、交易与配方

实际注册`life_sanctuary:shelter_compass`与`life_sanctuary:skylight_shelter_compass`，最大堆叠1。普通版已加入新植物商人独立交易，暂定8绿宝石换1枚，common配置`plantMerchantCompassEmeraldCost`可在1～64调整；8是本轮实现的可调默认值，不是用户已确认的最终平衡价格。旧商人不重置交易表。

升级配方为实际原生shapeless recipe，可使用已绑定普通指南针，但输出是未绑定的天窗版；不继承错误类别的普通庇护所坐标或编号。合成消耗和产物交付由原版合成系统处理。图标和转针沿用原版compass模型及完整angle相位，暂未制作两种专用贴图。

## 绑定与重复目标

服务端右键选择当前维度内、对应类别、水平距离最近的已登记目标；等距按稳定编号择先。只在主动使用时查询，20刻使用冷却，不在物品inventoryTick中执行定位。

查询前检查玩家生存背包／快捷栏／装备槽和副手中的其他庇护所指南针，将其有效绑定坐标排除；使用中的这枚不排除自身。两枚分别使用会获得不同目标，更多枚同样适用。不同玩家不互相占用；箱子、末影箱及套在其他物品里的指南针不参加当前背包排除，已经相同的复制品不会被后台自动改写。无剩余目标、维度不匹配或索引只读时保留旧绑定，动作栏提示失败，不清空原坐标。

CUSTOM_DATA的ShelterTarget保存真实结构ID、GlobalPos、结构起始区块、类别及编号；写入时保留其他根自定义数据。同时写入原生LODESTONE_TRACKER，tracked=false，目标不要求现场有磁石；物品继承Item而非CompassItem，不调用原版磁石失效清理。客户端只使用原生CompassItemPropertyFunction显示方向，跨维度时沿用原生无法指向的表现，不会假装可以跨维度导航。

## 真实结构索引与编号

ShelterLocations SavedData固定存主世界`life_sanctuary_shelters`，以结构ID＋维度＋结构起始区块识别唯一庇护所，记录真实结构包围盒中心为目标。两类各自编号1→A、26→Z、27→AA、702→ZZ、703→AAA。重载、再次定位和不同玩家不会重新编号；类别分开，因此普通A与天窗A是不同记录。

正式Structure通过以下标签加入类别：

- `life_sanctuary:shelters`：普通庇护所。
- `life_sanctuary:skylight_shelters`：天窗庇护所；同时属于两标签时按天窗类处理，普通查询不包含。

标签资源当前为空，因为项目尚无正式庇护所Structure；没有填入村庄、猜测ID或假坐标冒充。ShelterDiscovery监听实际区块加载，把有效StructureStart延迟到服务器tick末登记，每tick最多256项；不在ChunkEvent回调中触发世界读取、区块加载或主世界SavedData初始化，不周期遍历世界。现有／新生成结构加载后都可纳入，重复登记沿用原编号。

生成作者也可在服务端主线程调用`ShelterLocations.observe(level, realStart)`；定位作者通过`ShelterLocators.register`提供有明确搜索预算、能排除已绑定目标的最近真实StructureStart。各provider候选经真实注册结构／类别标签验证后进入统一索引，再从已有和新候选中选择最近者。provider必须遵守最近和排除契约；不能只拿原版findNearestMapStructure命中一个已排除目标就声称不存在第二个目标。

**目前只实现已登记真实结构的最近目标选择及后续定位适配接口，尚没有搜索未生成区域的provider。** 正式庇护所世界生成、布局、目标入口及搜索预算需要随其制作接入；现在没有真实目标时，指南针正确返回未找到，不能声称已经能定位未探索的庇护所。这是本条尚待正式结构集成的部分。

V1索引严格校验列表类型、正编号、类别内编号唯一、结构身份唯一及计数上界；未知版本或坏档保留原NBT并只读，拒绝覆盖或从A重新编号。损坏的物品目标元数据不视为有效占用。
