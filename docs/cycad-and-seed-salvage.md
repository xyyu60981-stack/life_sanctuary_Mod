# 苏铁搜索与成熟种子抢救接入

本页对应2026-10-27修订第9、12条。共享逻辑已实现，具体苏铁、死体与种子物品尚需物种作者注册和适配；不能把接口等同于游戏内容已经出现。所有空间尺寸为XYZ。

## 苏铁

使用 PlantSpeciesRegistry.registerCycad 注册定义，将水平种群边长设为32，保留原个体上限。随后通过 PlantCycadRules.register 登记真实产种范围和只读供粉者资格谓词，不设猜测的全物种默认产量。花结构与原种群花期入口保持原接入流程。

PlantFlowerRound 保存已尝试次数和当前2000活动tick进度。PlantCycadScheduler 复用基底区块活动时钟及到期队列，暂停／卸载不补算离线时间，不逐刻扫描植株或世界方块。仅允许能继续生命周期、完全成年、健康且未剪止的个体调度；当前须有一朵仍可受粉且仍附着的花，历史关闭花不占这个资格。

每满2000活动tick消耗一次搜索，最多三次。前两次只通过本物种、本种群索引寻找供粉者，第三次以自身基底为中心21×5×21，包含XZ各±10、Y±2。候选按基底归属，去除自身和不可用个体；不强制加载区块。无供粉者也消耗搜索次数，但不投概率。第三次在原成功率上加20个百分点、封顶100%，没有供粉者仍为0%。

失败前两次保留受粉资格；第三次失败才退出本轮受粉。花结构与供粉功能保留到花期正常结束，完全花也按此区分两种功能。成功后花进入受精状态，停止再次自然搜索。重复开启同一花期ID不会刷新失败预算，新花期才重新计数。PlantNaturalPollination 入口也检查到期和旧快照，避免重复调用重投概率。

## 枯死与种子

进入 PlantWithering 枯死状态时关闭未成熟花／种子，保留 SEEDS_READY 的实际成熟数量。独立环境适配器若在真正进入枯死结构前启动自己的程序，须在该时点调用 discardImmatureSeedsForWithering；这个入口只处理花数据，不替物种设置枯死状态。枯死中成熟种子仍通过原 takeSeeds 一次性取用。

PlantWithering.finish 在结构写入前快照仍附着的成熟种子；成功后将尚未被通知回调取走的数量转入 PlantSeedSalvage 台账，再注销活体身份与活动任务。优先绑定原花位置，若该格不保留死体则绑定基底，再无基底则绑定实际残留死体的最低位置。没有物理死体时不留下悬空采集点；水、空气等不能作为死体载体。

台账按原个体UUID和花键唯一标识，记录物种、位置、实际数量、死体方块注册ID。位置索引供准星交互查询，不靠扫描世界。已归档UUID不能复用创建新活体。

具体死体右键适配先通过 rescuedSeedsAt 查询，再验证权限、实际种子物品与背包容量，最后调用 takeRescuedSeeds。后者要求正确维度、服务器线程、区块可用、台账快照和实际死体类型一致，成功只取一次；不会自行投放物品。结构写入锁期间拒绝取用，避免方块通知回调重复领取。调用方仍负责物品事务，不能在取用后因容量错误丢失奖励。

真实死体被移除或换成其他方块后调用 discardRescuedSeedsAt，取消的破坏事件和区块卸载不得清除。通用植物结构提交在成功替换方块类型后已清理原位置台账，失败回滚不提前删除；具体方块回调在结构事务期间应跳过重复清理。普通方块放置、破坏等路径仍需实际死体适配器接入这个入口。

## 存档与验证边界

PlantIndividuals V14 新增花期 CycadAttempts／CycadElapsedTicks 与根级 RescuedSeeds。V13及更早合法数据迁移时尝试计数和进度为0、死体台账为空，保留原失败状态；不猜测历史死体种子。缺失或损坏V14必需字段进入只读保护并保留原数据。

全部源码使用本地NeoForge缓存依赖独立javac通过。规则程序覆盖三次预算、2000边界、概率和范围、种群索引迁移、重复判定拒绝、成熟／未成熟分流、台账往返与UUID保护；补叶和攀援回归通过。未运行Gradle或完整游戏启动，实际花模型、背包投放、死体破坏及多人交互仍需接入后的游戏验证。
