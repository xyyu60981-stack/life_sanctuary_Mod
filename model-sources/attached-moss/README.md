# 附着藓

零厚度贴面苔藓，只附着在完整方块的侧面。结构照原版藤蔓。

> 资源名用了 `attached_moss`（Minecraft 资源路径不能有中文），方块 ID 你们按大纲定，改的时候全局替换即可。

---

## 1. 结构

模型只有一个元素：**一片贴着方块面的平面**，离方块面 `0.05` 像素。

```json
{ "from": [0, 0, 0.05], "to": [16, 16, 0.05],
  "faces": { "north": {...}, "south": {...} } }
```

- `0.05` 偏移是为了**避免和身后的方块面 z-fighting**
- 双面都给：万一背后的方块被挖掉，从里面也还看得见
- **不能加 `cullface`**：身后就是实心方块，一加 cullface 这面藓直接被剔掉

---

## 2. 四个方向

一个模型 + 方块状态里绕 Y 旋转，和原版藤蔓一个套路：

| 方向 | y 旋转 |
|---|---|
| north | 0 |
| east | 90 |
| south | 180 |
| west | 270 |

同一格可以同时贴多面（墙角），multipart 天然支持。

---

## 3. 「不同方块之间的衔接」怎么处理

这是这个物种最关键的地方。

### 问题

一块藓的贴图铺满整个方块面。如果所有方块都用**同一张** 64×64，
相邻两格就是同一个图案并排——远看是一层规则的方格网，一眼假。

### 解决：四变体随机

1. 把 1254 的原图先缩到 **256**（保持苔藓绒簇约 7 像素，太大会糊成一片）
2. 从里面切 **4 块各不相同**的 64×64 子图
3. 每块各自做**无缝处理**（环绕混合，只羽化最外 35%，中间保持清晰）
4. 四块拼成 128×128 图集，四个模型各取一个象限
5. 方块状态里每个方向给 **4 个模型等权**，游戏按位置稳定随机挑一个

**为什么这样就够**：每块自身是无缝的，所以两块**不同的**藓相遇时不会出现"切断"的硬边，
只会是一次自然的图案过渡——方格感消失，又没有明显的接缝。

### 效果

| | 单图块 | 四变体 |
|---|---|---|
| 相邻方块 | 同一张图并排，方格明显 | 相邻格图案不同，看不出格子 |
| 边界 | 无缝 | 无缝 + 图案变化（不是硬切） |

## 5. 代码侧

按藤蔓来就行：

- 放置：目标面必须是**完整实心方块**的侧面，不满足放不下
- `canSurvive`：背后方块变软/破坏时掉落自身
- 四个布尔 `north/south/east/west`：放置和邻块变化时更新（照 `VineBlock` 的结构）
- **掉落**：整格掉 1 个（原版藤蔓就是这么做的），不要按方向数掉落

---

## 6. 边缘要不要做不规则

现在贴图满格不透明，一片藓的外轮廓是**正方形**。

做成藤蔓那种边缘留白会更自然，但代价是**相邻两块之间会出现透空的缝**，整面墙看起来有裂纹。

目前选择保持满格 + 四变体，等进游戏看实际效果再决定。

---

## 6.5 第二轮修正：共同边缘（common border）

第一版四变体虽然打散了重复，但**子图之间的边缘内容不同** ——
A 的右列和 B 的左列对不上，格子边界会留一条淡淡的错位线。

修法：所有子图的最外一圈都取自**同一块参考图**（第 1 块），向内 6 像素羽化回各自的图案。

- 任意两块相邻时，接触的两条边像素完全相同 —— **绝对无缝**
- 内部 82% 的区域仍然各不相同 —— 重复感依然被打散

**实测**（右列与左列的平均色差）：

| | 第一版 | 共同边缘版 |
|---|---:|---:|
| 不同子图之间 | 约 12~15 | **4.3 ~ 5.0** |
| 图集内部普通相邻像素 | 13.0 | 13.0 |

不同子图交界处的色差已经明显低于普通像素抖动 —— 看不出边界。

脚本：`tools/build_fuzhuoxian3.py`
