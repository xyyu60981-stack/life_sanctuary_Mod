# 培养柜基础接口

以制作大纲为设计参考，用户后续说明优先。当前只有规则和单阶段计时模型，没有实际柜体、库存、菜单、配方或红石事件接入。

## 已确认规则

- 四个培育槽，每槽投入一袋孢子；每袋对应四份培育结果。中间阶段转下一阶段保持四份，不再次乘四。
- 有红石信号时工作，断电暂停；不能因重复信号提前成熟或重置已选时长。
- 每段按对应物种自然耗时的 60% 培育，整数不足一刻向上取整。
- 培养柜内的配子体不执行自然环境死亡流程。
- 中间阶段可手工取出，自动化仅抽取最终阶段；最终完成槽数对应比较器 0、4、8、12、15。
- 上方输入、下方输出，侧面按许可槽位处理；不可因柜体信号传导意外锁住外部漏斗。
- 光照等级 10。外观遵循用户后续确认的完整方块、无开盖动画方案；尺寸与方块资源后续实现。
- 肋木的近水五日基础、直接培育、萍类走茎等例外由物种配方显式声明，不编造不存在的配子体或幼苗阶段。

## 当前代码

`CultivationRules` 集中四槽、每袋四份、光照及比较器规则。`durationFromNatural` 使用整数计算 3/5，避免长整型乘法溢出及浮点误差。

`CultivationProgress` 保存当前培育阶段、固定目标时长、已用活动 tick 和异常冻结标记。`start` 接受物种已选定的一次自然时长；`advance` 只累计机器调度明确提供的活动 tick，断电或异常不推进，最多到达当前阶段终点。它不会据世界时间、睡觉、卸载或离线自动补算。

`ready` 不表示物品已经产出。到期后必须由未来库存事务确认输入身份、目标槽位和物品交换，再推进阶段；轮询不能自行重复领取产物。`permits` 仅用于相同阶段的普通进度更新，拒绝目标重抽、进度倒退和失败解冻，不能代替阶段转换事务。

后续仍需配方注册与阶段输出映射、四槽库存事务、版本化保存、加载区块内调度、方块与菜单、物品能力及红石／比较器接入。本轮未运行 Gradle。

## 显式培育配方与注册

CultivationRecipe 保存配方 ID、物种 ID 和有序 Phase 列表。Phase 的 key 为稳定培育阶段键，output 为逻辑产物标识，实际 ItemStack 由后续适配器映射；不要求植物世界中存在相同名称的阶段。不存在的配子体或幼苗不要加入配方。

每段明确自然耗时范围，Phase.start 在输入／产物事务确认可开始时选择一次自然时长，再转换为 60% 机器时长。固定时长不抽随机，重复轮询不得重新调用 start。Phase.accepts 只检查已选目标和阶段是否符合该段范围，不代表库存内容或物品副作用已被验证。未知阶段不能被当作最终阶段；阶段链不接受重复键。

CultivationRecipes 在物种元数据之后配置，一个物种一个方案，配方 ID 与物种重复均拒绝。缺失配方不猜测。各段 outputCount 恒为四；中间转最终仍是四，不是十六。肋木五日基础等例外需在对应配方显式给出，当前没有注册任何真实物种配方。

尚未实现配方快照随在制任务保存、逻辑产物到真实物品映射、单槽／四槽库存事务或热重载；不能将此注册表理解为已可在游戏培育。
## 单槽批次模型

CultivationBatch 保存单袋独立 UUID、完整不可变配方快照、当前阶段下标及固定进度。阶段必须与配方内对应键／时长范围一致；同阶段普通更新不能改变身份或配方，不能跳阶段、倒退进度或解除失败。配方快照当前只在内存模型中保留，NBT 编解码尚未实现。

advance 只推进当前段，到期不会自动出货或连跳下一段；nextPhase 仅在中间段成熟时生成下一段状态提案，保留同一批次和配方。实际调用必须在转换事务确认条件后进行，并用预期批次核对提交，不能重复轮询旧快照反复抽时长。异常冻结不改变已有时长／进度，也不自动恢复。

manualProduct 在当前段成熟时描述当前产物；下一段尚未成熟时仍描述上一段四份中间产物，供手工取出并终止整批。首段尚未成熟没有中间产物。automatedProduct 仅在最终成熟时返回，失败冻结批次两者均不可取。查询返回逻辑产物，不生成 ItemStack；未来领取事务必须一起移除批次，防止重复领取。初始袋子的退回／取消策略尚未实现。
## 单槽批次存档接口

CultivationBatchCodec 使用独立 V1 格式保存批次 UUID、完整配方及有序阶段链、当前下标、已选目标时长、活动进度和异常标记。读取不访问实时配方注册表，不抽取新目标、不推进时钟、不启动机器任务；因此不会因新默认配方覆盖已经投入的批次。

Loaded 提供通过校验的不可变批次；Preserved 保留不支持或损坏的原始 NBT 副本及诊断原因，不可当作空槽重新投入。Preserved.data 每次返回副本，write(ReadResult) 对此结果原样写回，不将未知数据转为空或补默认值。字段类型、阶段链重复键、下标范围、当前阶段键／目标区间、进度越界及非 0/1 失败字节均校验。

未知物种／产物标识可作为字符串恢复到配方快照，不自动绑定当前默认配方；未来机器执行前还必须检查对应物种／产物适配器是否可用。当前未接入方块实体或四槽容器，不能据此宣称已有游戏保存重载功能。未进行运行时 NBT 往返验证；本轮仅静态核对读写字段及差异，未运行 Gradle。
## 四槽状态与提案

CultivationSlots 严格保存四个可选槽，每槽为空、Loaded 批次或不可读 Preserved 数据。同一批次 UUID 不能出现在两个已读槽。任一槽不可读时整机只读，不能投入、推进、领取或根据缺失 batchAt 认定为空；投入判断必须使用 canInsertAt。冻结的可读批次保持占槽。

insert 仅接收首段零进度且未失败的新批次；updateProgress 核对预期旧批次并只允许同段普通推进／冻结；continueBatch 只接收当前中间段成熟后的一段前进，保持批次和配方、新段零进度。所有接口返回不可变状态提案，不消费输入。

extract 同样要求预期批次，按手工／自动规则返回 Extraction（四份逻辑产物和清空该槽后的 after 状态）。调用方必须比较完整旧四槽快照，将 after 与真实物品交换一起提交；同一旧快照多次查询不会自动消除批次，因此不能在没有事务的情况下直接按结果发物品。模拟抽取仅查询，不能写回 after。容量不足、库存未知副作用及重入锁由后续真实库存事务解决。

比较器仅统计最终 ready 批次，按 0／4／8／12／15 输出；不可读整机返回零，中间产物不计完成。当前没有方块实体或物品能力实际调用，没有新增 tick，未运行 Gradle。
## 四槽整体存档格式

CultivationSlotsCodec 使用独立 V1 格式，固定四条显式槽记录，保存 Slot 编号、Occupied 标记及占用时的 Batch。读取按编号还原而非依赖列表排列；槽数量不足、索引越界／重复、错误类型、非 0/1 占用标记，以及空槽携带 Batch 均拒绝，不将缺失槽静默补空。

单个批次不可读时，其原 NBT 留在该槽并使 CultivationSlots 只读；整体容器结构错误或不同可读槽重复批次 UUID 时，整个原容器 NBT 转为 Preserved。两级 Preserved 都可原样写回，读取和返回的数据均作防御复制，不覆盖为默认空状态。外层 Loaded 仍须检查 state.isReadOnly，不能据 Loaded 就允许机器工作。

新方块创建时应明确初始化 CultivationSlots.empty；已有保存字段缺失或损坏不能调用 empty 作为恢复兜底。当前只是编解码接口，尚未挂接方块实体、能力或菜单；未进行游戏保存重进验证，未运行 Gradle。
## 事务控制器与库存边界

CultivationController 由未来服务器方块实体持有，在创建线程上使用。它保存外层 ReadResult，所有变更核对完整预期四槽快照；不可读、旧快照、无效槽或事务重入均拒绝。snapshot 在库存回调期间仍为提交前状态，不暴露半写入提案。CHANGED／RECOVERY_REQUIRED 返回后，方块实体必须标记保存及同步；当前没有方块实体实际持有控制器。

start 检查空槽、新批次身份与注册配方，构造首段提案后调用 Input.consumeOneSporeBag。true 才提交新批次；false 必须表示库存完全未变，保留原槽。若适配器抛错，可能已消费输入，因此保留新批次并冻结，既不重试扣袋也不自动退款。批次 ID 应由每次真实新投入生成，不复用历史 ID。

extract 同时准备清槽及完整四份产物，调用 Output.deliver；true 后提交清槽，false 保留原状态。抛错则冻结原批次并继续占槽，阻止未知出货结果再次领取。两个适配器都必须自行提供原子库存交换，不能部分写入后返回 false；这里不能替第三方库存回滚物品。模拟插入／抽取应使用不可变提案检查，不能将模拟返回 true 传入控制器作为真实成功。

advance 只提交同段活动进度；continueBatch 只在中间段成熟时选取并提交下一段，库存回调期间同样不能重入。控制器自身不调度 tick、不检查真实红石，也不绑定 ItemStack 或逻辑产物映射。未来机器调度仍需在有电、区块活动且处理器可用时调用；没有跨区块存档／外部库存的崩溃原子性保证。未运行 Gradle。
## 满孢子袋输入适配

CultivationSporeBagInput 实现可信 Input 边界，从调用方明确指定的 Container 槽消费一袋。创建时保存完整 ItemStack 副本；执行前要求现存数量和物品／组件仍与快照相同，并确认是满孢子袋及对应物种。空孢子袋、花粉袋、其他物种均不消费。标签兼容本 mod 旧无命名空间物种名及完整 ID，外部命名空间不按 path 混同。

removeItem 后严格检查返回恰好一个原物品，以及源槽恰好剩余原数量减一，再标记来源容器变化。修改前条件不满足返回 false；开始修改后的异常结果必须抛错，交由控制器冻结新批次，不把可能已扣物品的情况当成普通拒绝。Container 若有其他第三方副作用，不能由此接口保证回滚。

此适配器不搜索背包／相邻容器，也不自行决定可访问的侧面。调用者必须先校验手工访问权限或自动化侧面抽取许可。尚未有培养柜方块、菜单或能力调用该适配器，未运行 Gradle。
