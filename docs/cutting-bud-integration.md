# 扦插临时芽丛接入

对应修订第10条。PlantCuttingBuds仅管理扦插建立阶段的临时芽丛；未注册真实扦插物种或模型，不添加猜测物品ID。根座只改变原下茎材质表现，下茎沿用该植株原有身份和归属。

## 物种接入顺序

1. 注册真实物种后登记 PlantCuttingBuds.Profile，明确扦插阶段键、临时芽丛部件role及只读Builder。
2. 正常结构事务成功放置带根座材质的下茎，并在个体基底登记其部件归属；此时不放芽丛。随后调用 establish，芽丛位置固定为基底上方一格。重复调用拒绝，不重抽时长。
3. Builder到期提供仅新增该芽丛一格的 PlantStructurePlan，依赖中须包含原下茎。半格模型、碰撞与选框由具体物种提供；共享层不以空方块或新的根座身份冒充模型。受阻返回Optional.empty，不能在Builder内直接改世界、生成掉落或修改个体。
4. 临时芽丛被玩家、机械或其他途径破坏时，方块适配器调用 breakBud，并阻止原版再次发放掉落。该入口使用抑制掉落的结构移除，不生成草杆或芽丛物品；不要再转入普通芽丛损毁枯死流程，也不要在isApplyingStructure期间重复处理回调。

## 生命周期

首次生成与每次真实破坏后均单独抽取12000～24000活动tick，含两端。普通成长计时暂停并保留原进度，芽丛实际生成后恢复；基础阶段接口、通用结构阶段提交和直接个体阶段替换均禁止等待期间跳阶段。原采集／繁殖额度不会刷新。

队列依附基底区块，不逐株逐刻扫描；区块不活动、服务器冻结时不计时。气候暂停、缺水等环境原因或剪止会暂停芽丛计时，恢复后继续剩余时长。物种下茎与空间判断在到期准备结构时由适配器补全，并由通用事务复核完整快照；受阻后保留已等待完的状态，每1000活动tick重试。受阻重试的临时退避进度不单独持久化，重载后再等1000刻重试，成熟等待本身不会重来。

普通回滚不把芽丛标为存在。需要恢复的事务按已提交归属记录对齐芽丛状态，环境恢复标记继续阻止自动成长；回调异常保留失败状态，不反复执行可能部分成功的世界操作。共享代码只提交结构，不自动发物品或音效。

成功进入其他阶段后清除临时芽丛循环，之后按该物种正常芽丛与生长逻辑处理。注销个体取消任务，带临时芽丛的个体不允许通过通用拆分／合并丢弃历史。自然静止植株不能初始化这个循环；已放置装饰植株也不应由物种适配器登记为可成长扦插。

## 存档与验证

PlantIndividuals V15新增根级CuttingBuds列表，包含Owner、Stage、Role、Position、TargetTicks、ElapsedTicks、Present、Failed。严格检查计时范围、布尔值、归属和实际部件索引。更早版本迁移为空，不根据现有模型猜测扦插来源；新版本字段损坏进入只读保护。

全源码本地缓存依赖独立javac及规则程序通过，未运行Gradle。已检查时长边界、重复调用不重抽、暂停／恢复、阶段绕过拒绝、再生时长重置、V15往返、V14迁移及注销清理；具体世界方块、真实破坏和半格模型需后续游戏验证。
