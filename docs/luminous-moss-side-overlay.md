# 光藓基底侧面覆盖

用户明确图集下排中、右两块64×64纹理用于下方基底的外露侧面，而非光藓本体侧边。对应204×136图集像素范围 `(70,70)-(134,134)`、`(138,70)-(202,134)`。PNG保持原样，未修改原始模型目录。

客户端在区块网格烘焙阶段检查光藓下方基底。只有完整碰撞立方体才绘制侧面覆盖；每个水平邻格为真正空气时显示该面，水、植物、玻璃等非空气邻格不算暴露。非完整基底不强行套用完整立方体外壳。覆盖采用透明 cutout 叠层，底下石头、原木等原材质保留，未把基底替换为其他方块。

覆盖模型挂在光藓模型上，向下延伸16像素，侧面外移0.01像素避免重面闪烁。四面各有两套单面平面模型；按基底位置与方向稳定选择两种纹理，不依赖世界随机流、不每帧抽取、不随年龄或采集改变。不使用光藓同高度邻格的 cullface 判断，曝光掩码由下方实际邻格计算。

`LuminousMossOverlayModel` 仅由客户端入口注册，包装 age=0/1/2 的方块模型，不包装物品。一次资源烘焙预建256种侧面／变体组合的不可变面片列表；每次区块编译最多读取基底和4个邻格，不新增方块实体、服务器属性、SavedData、计时器、网络包或主动逐帧绘制。没有任何方块状态写入，因此不因覆盖本身触发侦测器。

方块变化沿用原版区块网格刷新；已核对本地依赖中 LevelRenderer.setBlocksDirty 包含各轴±1范围，覆盖基底侧邻格至光藓位置的对角关系。仍需实测区块边界、纵向区段边界、资源重载以及实际使用的光影／渲染优化模组；此实现不宣称已完成游戏兼容验证。常规 frustum 或光照表现也应在这些边界重点检查。

本体1像素薄层的四面改用其顶面纹理的边缘行，避免继续误用两块基底覆盖图。模型其余几何和UV不改。

维护工具：`tools/update_luminous_moss_overlays.py`。工具校验图集尺寸，再重建8个覆盖模型与3个本体边缘UV；不会编辑PNG或原始文件。资源回归工具已加入覆盖方向、向下范围和64×64取样范围检查。

验证：完整源码独立编译通过；稳定变体与遮挡掩码编码检查通过，8个覆盖模型和3个本体边缘检查通过。未运行Gradle或Minecraft；视觉效果、遮挡变化、采集后的残留检查和光影表现仍待游戏验证。
