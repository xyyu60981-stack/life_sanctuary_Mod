# 培养柜基础架构进展（2026-10-25）

本记录汇总上次归档后本会话已完成的培养柜基础。具体物种设计、模型仍交由后续作者按确定规则接入；其他植物基础现状沿用 architecture-handoff.md 和上次进度记录。

## 已接入

- 卧式光照培养柜单格两槽，两个同朝向左右相邻单柜配成大型四槽柜；第三柜不并入。柜体、物品、实体、菜单和客户端屏幕均已注册，外观暂用静态铁块材质。
- 每半柜独立保存两槽，四槽仅是共同访问视图；拆一半不转移另一半的植物。邻柜区块未加载时暂停访问，重新加载后复核，不强制加载。
- 满孢子袋主／副手直投、UI 点击与 Shift 投入、玩家 UI 手工领取；潜行右键不打开柜体，允许放置手持方块。
- 顶部只进，下方仅最终产物输出；支持漏斗单件抽取和不可堆叠产物。侧面／无方向暂不提供能力。
- 最终产物在首次真实自动抽取时与清除原任务一起转成剩余实物；模拟不扣物品或抽时长，剩余取完前继续占用原名额。
- 余量保存到柜体和掉落物，重放继续读取。未知数据保留只读；库存结果不确定时冻结，不重复出货或自动退款。
- 通电活动 tick 独立推进，防同 tick 重复调用；空柜／全部完成或冻结提前结束。柜体非红石导体，防止经自身间接锁上下漏斗。
- 比较器按完成名额输出，单柜 0／8／15，大柜 0／4／8／12／15，余量取完才释放对应完成名额。
- 原版旋转／镜像入口及半柜左右标记处理；缩小邻居变化触发的配对复核范围。
- UI 预览不可作为真实物品直接搬走；服务端事务处理输入／领取。按状态变化缓存预览，量化进度及物品差量同步，显示阶段、物种和实际余量。
- 管理员只读 inspect 和 recipes 命令，附游戏验证清单与物种作者接入说明。

## 验证与工作区

用户已逐步运行 compileJava 并反馈成功，包含最近的物种预览显示。本会话未运行 Gradle；静态检查包括接口引用、差异空白、语言／资源 JSON 和部分源码定界符检查。

没有实际游戏测试结果。完整输入输出流、保存往返、结构模板、跨区块、机械动力／航空学和大规模性能仍需按 cultivation-verification.md 验证。弃用 API 提示曾因终端编码显示乱码，连接代码已替换已知 hasChunkAt 弃用调用；另一次命令尾多带乱码导致未知参数，重新输入命令后用户确认成功。

本轮未提交或上传代码。原有 gradle.properties 本机代理配置、构建辅助脚本及文档提取文件继续保留原状。
