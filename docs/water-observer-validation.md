# 水生结构与侦测器验证

规则：保留水状态不等于屏蔽方块更新。水中长出植物、植物移除恢复为水，均应通过原版更新路径触发侦测器。

## 当前实现

- 结构先以延迟邻居通知的方式写入，成功登记归属与额度后，再通知实际发生变化的位置。
- 判断依据是前后 BlockState，而不是 FluidState。即使水状态相同，植物出现或移除仍属于变化。
- 每个变化位置执行一次 updateNeighbourShapes 和普通邻居通知；前者到达原版 ObserverBlock.updateShape。
- 不直接设置侦测器 POWERED，不自行安排额外红石脉冲，不另写一次相同方块来强行触发。
- 前后 BlockState 相同的方案项不主动通知；仅内部额度或归属变化不应凭空触发脉冲。
- 未修改的依赖位置只用于验证，不主动广播更新。

## 后续游戏验证

具体水生方块适配接入后，在静止水源中测试；让侦测器检测面朝向目标格，并使用脉冲计数装置记录输出。
每个动作之间至少间隔 10 个游戏刻，保证侦测器已经完成上一轮脉冲，排除原版脉冲合并的影响。

| 场景 | 预期水状态 | 预期输出 |
|---|---|---|
| 水格长出植物 | 与放置前完全一致 | 一次脉冲 |
| 移除植物恢复水格 | 与移除前完全一致 | 一次脉冲 |
| 原状态与目标状态相同 | 不变 | 不因该方案额外产生脉冲 |
| 仅内部额度更新 | 不变 | 不产生脉冲 |
| 预检因额度、空间或归属失败 | 不变 | 不产生脉冲 |
| 水流中的合法保流态植物出现/移除 | 流态完全保留 | 每个独立动作一次脉冲 |

水流场景仅在物种方块确实支持相同流态时执行，不能用仅支持水源的含水方块强行替代。
同时观察基底、邻格植物与红石更新是否正常，确认成功动作不会在后续刻自行重复触发。
多方块一次操作可能改变多个被观察的位置；原版侦测器在已有待执行 tick 或脉冲期间会合并更新，
本接口遵循原版行为，不承诺高频连续操作的每次更新都被独立计数。

失败回退不由提交器主动广播成功通知；第三方方块回调引发的红石等外部副作用不能用方块回退撤销。
